Tabs

A tablist over projected <gog-tab> children. Each tab declares its own label, icon and disabled state, so a tab is written in exactly one place — and the header row is built from that.

Lazy content

An <ng-template gogTabContent> is built on first activation and kept alive afterwards. Which behaviour you get is decided by whether the template is there — there is no lazy input to keep in sync.

Overflow

Too many headers to fit scroll inside a <gog-scroll>, not a native overflow-x — a native scrollbar is the one strip of chrome no --gog-* token can reach.

scrollActiveIntoView (on by default) keeps the active header in view, centered where there's room — the same "show what's around the current position" idea gog-paginator uses for pages. Jump around with the buttons below, or arrow through the header row itself, and watch it scroll. Toggle it off to see the header stay put instead. showScrollTrack shows the horizontal scroll thumb; unset, it defaults to the opposite of scrollActiveIntoView — auto-scrolling and a visible track being slightly redundant affordances for the same "where am I" question.

Loaded from a backend

Both the tab list itself and each tab's own content arrive asynchronously — the shape of a real app, where <gog-tab> comes from an @for over a signal a service fills in, and a gogTabContent template fetches its own data on first activation. <gog-tabs> stays mounted the whole time with zero tabs at first — nothing special to opt into, the header row and activeIndex just follow whatever is currently projected.

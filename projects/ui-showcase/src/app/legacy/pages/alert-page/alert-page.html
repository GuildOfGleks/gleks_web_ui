Alert

A persistent, in-flow message. Unlike a toast it has no timer, no queue and no overlay — it renders where you write it and stays until your app removes it.

Dismissible

dismissed is pressed, not removed — the alert stays in the DOM and the app decides. That is deliberate, and it is what makes the focus problem solvable: the handler runs while the alert is still mounted and its close button still has focus, so there is somewhere to move focus from. A component that deleted itself would have destroyed the focused element before anyone could react. This example moves focus to the button that replaces it — the library cannot pick that destination, only your app knows it.

@if (showDismissible()) { The card issuer declined the charge. No money has left your account. } @else { Bring the alert back }

Icons

Each severity brings its own glyph. iconName overrides it, and null removes it for a message whose words already carry the meaning.

An iconName overrides the severity's own glyph. [iconName]="null" suppresses the icon entirely. A projected gogAlertIcon template replaces it with your own markup.

How it announces

live is 'assertive', 'polite' or 'off', defaulting from the severity — danger and warning interrupt, the rest wait. Set 'off' for a message that is already on the page when it loads: the default is wrong for exactly that case, and the component cannot tell it apart from a message that just appeared. The announcement itself lives in a visually-hidden region beside the alert, empty until one render after the alert mounts — a live region filled in the same pass as its own creation announces nothing.

Interrupts. For something that just happened and changes what to do next. Waits for a pause in what the reader is already hearing. Announces nothing. This is the one to reach for on a message rendered at page load.

Long content

The body wraps and the icon stays at the top, so a paragraph does not centre its glyph against the middle of the text.

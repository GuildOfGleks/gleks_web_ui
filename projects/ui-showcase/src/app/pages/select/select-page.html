clear button × size

The clear button appears only once something is selected, so a field no longer needs a fake "— not selected —" option to let people undo a choice. It is the one part of the trigger that is not the trigger button: nesting a button inside a button is invalid HTML, so it is a sibling positioned over the trigger's end edge.

fullWidth and minWidth, in a 20rem container

With [fullWidth]="false" the trigger sizes to whatever is currently selected, so a short option collapses it; minWidth is the floor under that.

appendToBody, and the panel size that comes with it

dropdownWidth and dropdownMaxHeight take any CSS length and apply only while the panel is appended — an inline panel matches the trigger through CSS. The capped field below holds 20 options in 160px, so the panel scrolls. The first two fields sit in a box with overflow: hidden and are pinned to dropdownDirection="down", so which way they open does not depend on where the page happens to be scrolled: open both and only the appended one survives the box.

virtualize

Both fields hold the same 10 000 options. Open each and watch how long the panel takes to appear: the windowed one keeps about twenty rows in the DOM whatever you scroll to, the eager one builds all 10 000 to show six. It is off by default and never switched on at a row count — Ctrl+F finds only the rendered rows, and CSS targeting :last-child matches the last rendered row. The announced count stays honest either way: aria-setsize carries the real list.

size × state

There is no clear button in this matrix and no chevron either: clearable is false here as it is on gog-select, and this control has no chevron at all — the trigger is a text field, not a button, so nothing claims it is a list you can open by clicking. [loading]="true" puts a spinner in the trailing slot for a source that is still fetching.

the trailing slot: clear button, spinner, or both

clearable is opt-in here, and what it watches is the text, not the selection: type two letters into the third field below and the clear button appears before anything has been picked, because on this control the two can disagree. Clearing empties both and emits gogSearch with an empty query, so a server-backed list resets with it. The spinner sits in the same slot and the field reserves room for both.

fullWidth and minWidth, in a 20rem container

Unlike the two listbox controls, the trigger here does not size to its content — it is an <input>, whose intrinsic width is the browser's own 20-odd characters. So [fullWidth]="false" gives you that default box and minWidth is the floor under it.

a field with no visible label

ariaLabel names a field that has no label. With neither, the placeholder is the fallback accessible name — better than nothing, but it disappears the moment anything is typed, which is why it is a fallback and not the plan.

a disabled option, and the empty message

optionDisabled defaults to the disabled property, so a GogDropdownOption carrying it needs no binding: the row stays in the list, reports aria-disabled, and neither the pointer nor Enter picks it up. emptyMessage replaces the list when the query matches nothing — type zz into the second field.

filterLocal and filterMatch

Local filtering is on by default and matches the query as a case-insensitive substring of the resolved optionLabel. filterMatch swaps in any predicate: type b into both fields below and the default keeps eight cities — Barcelona, Berlin, Bratislava, Brussels, Budapest, plus Dublin, Lisbon and Zagreb — where the prefix matcher keeps five. Turn filterLocal off when gogSearch fetches an already-filtered list, which the Searching section below does.

four inputs that do nothing here

filter, filterPlaceholder, filterPosition and filterEmptyMessage are in the API table because the compiler puts them there: this control extends the same GogDropdownBase as gog-select, and they describe the search box inside a panel. There is no such box here — the trigger is the search box — so binding any of the four changes nothing. The two that do carry over are filterMatch, which the local filtering above reads, and emptyMessage, which is this control's own input and not filterEmptyMessage.

minLength × openOnFocus

Focus each field without typing, then type one letter. openOnFocus is on by default and shows the whole list before minLength would have let anything through — including when the field already holds a selection, whose label would otherwise have filtered the list down to itself. With it off, nothing opens until enough has been typed.

a server-backed field

The three inputs that make one: (gogSearch) runs the lookup, [loading] shows it is running — a deliberate 600 ms here — and [filterLocal]="false" stops the answer being filtered a second time. That last one is the bug worth naming: the server matched on fields this component cannot see, so filtering its reply against the same query silently drops rows. appendToBody, and the panel size that comes with it

dropdownWidth and dropdownMaxHeight take any CSS length and apply only while the panel is appended — an inline panel matches the trigger through CSS. The first two fields sit in a box with overflow: hidden and are pinned to dropdownDirection="down", so which way they open does not depend on where the page happens to be scrolled: type in both and only the appended one survives the box.

virtualize

Both fields hold the same 10 000 options. The windowed one keeps a dozen rows in the DOM whatever you scroll to — as many as the panel shows, plus a margin — where the eager one builds all 10 000 to show six. Off by default and never switched on at a row count — Ctrl+F finds only the rendered rows, and CSS targeting :last-child matches the last rendered row. aria-setsize still carries the real list either way, and the arrows still walk all 10 000: End reaches the last one. Focus is not at risk here the way it is on gog-select — this is a combobox, so focus never leaves the text field and a row leaving the window cannot take it with it.

gogLoadMore

Fires when the panel is scrolled to the end of the list — the signal to fetch and append another page rather than handing 200 rows over up front. It is the other half of the problem from virtualize: this keeps the number of records the server sends small, that keeps the number of rows the browser builds small, and neither implies the other. Open the panel and scroll to the bottom to load the next 20.

[(value)], and the text that is not the value

The field holds two things: what is typed, and what is committed. Pick Berlin, then edit the text — the value stays Berlin until the edit resolves, and Esc or clicking away snaps the text back to it. That is forceSelection, on by default, and it is what keeps a user who typed one character to refine a search from silently losing what they had picked.

panel and options

The panel exists only while it is open, so each line below reads "no element matches" until its own field is focused — then it fills in and follows it. The rows are plain divs with role="option" and no tabindex: they are never focused and never tab stops, because the whole keyboard contract lives on the input — the arrows highlight, Home and End jump to the ends, Enter picks the highlighted row and does nothing when there is none, Esc closes and restores the text, Tab closes and moves on.

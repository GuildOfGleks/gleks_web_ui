Hold any of these down. The background deepens one step past its own hover, so the press is visible even while the pointer is hovering the button — and it is a state rather than a movement, which is the point: turn on prefers-reduced-motion: reduce (DevTools → Rendering → Emulate CSS media feature) and the scale() goes away while the colour stays. Until 21.8.1 the scale was the whole press, so that reader pressed a button and nothing happened at all. The ripple does not cover this: it is off by default, and it is suppressed under reduced motion on purpose, because a ripple really is decoration and a press state is not.

Links that look like buttons — [gogButton]

gog-button renders its own <button>, so it can never be a link. [gogButton] inverts that: you keep your own <a> or <button> and the directive gives it the button's look. Nothing is brokered through an input, so routerLink, href, target, download and any directive of your own keep working — they were never taken away.

ARIA state — a toggle and a disclosure

The component hides the real <button>, so [attr.aria-pressed] written on <gog-button> lands on the custom element host — which has no role — and reaches no assistive tech at all. It compiles, throws nothing, and looks right. Use the inputs: ariaPressed, ariaExpanded, ariaControls and ariaHasPopup, alongside the ariaLabel that already existed for the same reason.

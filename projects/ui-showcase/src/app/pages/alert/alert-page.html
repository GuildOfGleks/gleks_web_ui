dismissing, and where focus goes

Press the close button, from the keyboard for the full effect. The handler hides the alert and moves focus to the button that replaces it. That is possible only because the alert did not remove itself: when dismissed fires, the close button still exists and still has focus. A component that deleted itself would drop focus to <body>, and a keyboard reader would start the page over. Where focus should land is the app's to know.

mount each one and read its region

A live region only announces text that arrives after it exists, and an alert shown with @if arrives with its text in one go. So the alert renders a separate, visually hidden region beside itself, empty, and copies its heading and body into it one render later. Mount a row and the region's attributes appear beside it; 'off' renders no region at all, so its row finds nothing to read.

set live="off" for a message that was there on arrival

The default is right for a message that appears in answer to something — a submit that failed. It is wrong for the commonest case: an alert rendered with the page, which would interrupt every visit about something the reader has not reached yet. The component cannot tell the two apart, so that call is yours. Every alert above the Announcing section on this page is live="off" for exactly that reason.

the copy stays

The hidden copy is not removed after it has been announced, so a screen reader reading down the page meets the message twice: the visible text, then the copy. It is also taken once — if the alert's text changes later, the copy keeps the old text and the change is not announced. Both are filed; until then, an alert whose text changes in place is better rendered again than edited, and one that never needs announcing should be live="off".

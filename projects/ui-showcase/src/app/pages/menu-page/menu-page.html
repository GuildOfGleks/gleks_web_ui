gog-menu

Menu

A command menu opened from a button you own. [gogMenuTrigger] goes on your button, gogMenuItem on your items — so an item can carry an icon, a label and a shortcut hint without an input per piece. A closed menu renders nothing at all.

Playground

Open it, then use the keyboard: ↑/↓ move and step over the disabled item, Home/End jump to the ends, Enter runs one, Esc closes and puts focus back on the button.

Document actions

Last action: {{ lastAction() }} · closes: {{ closes() }} (gogClosed fires however the menu closed — item, Esc, Tab or a click outside).

Row actions

What the component was built for: an icon button per row. [appendToBody]="true" because gog-table wraps itself in a gog-scroll, which would otherwise clip the panel — the same reason the dropdowns have that input.

Inside a scroller, with and without appendToBody

The left menu is inline: it is clipped by the scroller's own box, which is what overflow does to any absolutely positioned child. The right one is portaled and escapes. Scroll the strip to see the difference — this is the one input to reach for when a menu appears cut off.

Direction

direction is 'auto' by default: the panel drops down whenever it fits and flips up only when it cannot — unlike a select's listbox, which picks whichever side has more room. Force it with 'up' or 'down'.

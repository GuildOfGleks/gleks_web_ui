state × mode

showThumb turns the control into a meter-like bar that still answers the pointer and the keyboard — there is simply nothing drawn to grab. Disabled dims the whole control once, label and error included.

min, max and step

The readout reserves the width of the longest number min, max and step can print and uses tabular figures, so it never shifts as the value changes — drag any of these and the label beside it stays put. The value is printed as a plain number: there is no formatter, so a unit or a currency belongs in the label.

orientation="vertical"

The same native input, turned with writing-mode, so dragging, touch and every arrow key keep working. The value grows upward, like a fader. A vertical slider is as wide as its content and its length comes from --gog-slider-vertical-length, which is why fullWidth does nothing here.

fullWidth

On by default — the opposite of the other controls, because a track has no content to size to. Turned off, it takes --gog-slider-auto-width (240px) instead of shrinking.

[(rangeValue)]

Each thumb is its own native input and its own Tab stop, and neither can pass the other — a drag that tries stops where the other thumb is. Only the thumbs take the pointer in this mode; a press on the bare track does nothing, which is the price of two inputs sharing one track.

thumbs that meet

Both thumbs start at 200 below, on top of each other at the end of the track. Drag left: the start thumb comes away. Until 21.15.0 it could not — the end thumb was always the one under the pointer, it cannot go past max or below the start thumb, and a mouse or a finger had no way out; only the keyboard did.

startDisabled and endDisabled

Pin one end and leave the other movable. They add to disabled rather than replace it, and only the pinned thumb dims — the track stays live for the other. A start thumb dragged onto a pinned end comes off it again the same way as above.

[(value)], and the keyboard

The keyboard is the native range input's: the arrow keys move one step, Home and End jump to min and max, and Page Up / Page Down take larger steps. valueChange fires on every step of a drag, not once at the end of it.

a value outside min and max

The control draws a value clamped to [min, max] but does not write the clamp back: bound to 150 with max at 100, it shows 100 and the model still reads 150 until someone moves the thumb. Clamp at the source if the model has to agree.

input attributes

Read from the live DOM. A visible label names the input through its for, so no aria-label appears on that row; without one, ariaLabel does, and with neither the input is still named — "Slider", which says nothing, so do not ship that row. The explicit aria-value* attributes repeat what the native input already exposes and follow the value as it moves.

range thumbs

One <label> cannot name two inputs, so each thumb carries its own aria-label: the label — or ariaLabel when there is none — followed by "Minimum" or "Maximum", or by startAriaLabel / endAriaLabel. Before 21.15.0 the ariaLabel row read a bare "Minimum". Each thumb's aria-valuemin/max narrows to the other thumb, since that is as far as it can go.

pointer targets

In single mode the whole track is the target — a press anywhere on it moves the thumb there. In range mode only the thumbs are, and they take the pointer at about 16px, under the 24px that WCAG 2.5.8 asks for. The keyboard reaches both thumbs fully; the pointer gap is filed in the backlog rather than papered over here.

gog-scroll

Scroll

A drop-in replacement for a native overflow: auto region: the content still scrolls natively, only the browser's own scrollbar chrome is hidden and replaced with a themeable, draggable overlay thumb. This whole page is scrolled by one — see the app shell around this content.

showTrack & focusable

[showTrack]="false" drops the overlay thumb/track entirely — scrolling itself (wheel, touch, keyboard) is unaffected, only the visual affordance is gone. Also settable app-wide via GOG_CONFIG.scroll.showTrack. [focusable]="false" takes the viewport out of the tab order — for a gog-scroll nested inside another focus-owning component (a dropdown panel, a dialog body) that already manages focus itself.

Scroll chaining

overscrollBehavior controls what happens once a scroll gesture hits this instance's edge. "auto" (the default) chains it to the next scrollable ancestor — scroll to the end of the box below and keep scrolling with the same gesture: the page itself keeps going, exactly like a native overflow: auto div. "contain" stops the gesture dead at the edge instead — suited to overlay-style panels (which is why gog-select's option panel and gog-dialog's body set it explicitly). To change the app-wide default instead of setting the input on every instance, call provideGogConfig({{ '{' }} scroll: {{ '{' }} overscrollBehavior: 'contain' {{ '}' }} {{ '}' }}) in your app's providers — every unset gog-scroll instance falls back to it.

overscrollBehavior="auto" (default)

@for (paragraph of paragraphs; track paragraph) {

{{ paragraph }}

}

overscrollBehavior="contain"

Already used inside existing components

Labeling

showValue="false" hides the numeric readout. With no label, use ariaLabel so assistive tech still gets a name.

Orientation

orientation="horizontal" (default, used everywhere above) or "vertical" — the developer picks per instance, there's no global default for this since it's a layout decision, not a house style. Both are backed by the same native <input type="range">, so dragging, touch, and keyboard (Up/Down as well as Left/Right) all work the same either way. Value increases upward for a vertical slider, same convention as a volume fader.

Range

range switches to two thumbs for picking a span instead of a single value — use [(rangeValue)] (a {{ '{ start, end }' }} pair) instead of [(value)]. Each thumb is a real, independently focusable <input type="range">, and neither can be dragged past the other.

Price range is {{ priceRange().start }} – {{ priceRange().end }}.

Range — one-sided disable

startDisabled/endDisabled pin just one thumb while leaving the other draggable — unlike disabled, which still turns off both together (that one's unchanged; a single [formControl]'s own disable state still speaks for the whole range, since one FormControl can't target just one thumb).

Full width

Full width of its container by default (see every slider above). A slider's track has no content of its own to shrink-wrap to, so [fullWidth]="false" instead sizes it to --gog-slider-auto-width (240px by default) — a fixed, themeable fallback rather than a content-derived one.

Validation

`errorMessage` is consumer-controlled: `gog-slider` just renders whatever it's given, for as long as it's non-empty — this page recomputes it every time the value changes.

Reactive forms — automatic error timing

With errorDisplay="auto" and a [formControl], the slider shows the error once it's been touched (drag it, then click elsewhere) and is invalid, instead of the page computing that timing.

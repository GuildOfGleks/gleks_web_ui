The clear button is here without anyone asking for it: unlike every other control, clearable defaults to true on this one, because it shipped a clear button before the input existed. [clearable]="false" drops it.

the +N overflow summary

Ten of twenty countries are selected below — more than the trigger fits on one line. The labels are measured with canvas.measureText rather than by rendering candidates, as many as fit are kept, and the rest collapse into +N. The count is aria-hidden; hover or focus the trigger and the whole selection is listed in its tooltip, which is bound only while something is actually hidden. Drag the window narrower to watch the split recompute — it follows the container, not a render.

fullWidth and minWidth, in a 20rem container

With [fullWidth]="false" the trigger sizes to its own summary text, so an empty selection collapses it; minWidth is the floor under that.

the two icon slots, and a field with no visible label

gogDropdownChevron replaces the chevron — and with it the up/down swap the built-in one does, which is the template's to draw — while gogMultiselectClearIcon replaces the glyph inside the clear button, not the button itself, so its accessible name is still clearAriaLabel. ariaLabel names a field that has no label at all.

a disabled option

optionDisabled defaults to the disabled property, so a GogDropdownOption carrying it needs no binding. A disabled row stays in the list and is announced as disabled; neither the pointer nor "select all" picks it up.

filter

Worth turning on past about seven options. The default matcher is a case-insensitive substring on the resolved optionLabel; filterMatch swaps in any predicate. Both fields below hold the same 20 options.

showControls × controlsPosition

The row is sticky at whichever end it is given, so it stays reachable in a long list. "Select all" acts on the options currently visible, which is what makes it mean something under an active filter — type "1" in the field below and it selects the eleven countries that match, not all twenty. Disabled options are never picked up.

appendToBody, and the panel size that comes with it

dropdownWidth and dropdownMaxHeight take any CSS length and apply only while the panel is appended — an inline panel matches the trigger through CSS. The first two fields sit in a box with overflow: hidden and are pinned to dropdownDirection="down", so which way they open does not depend on where the page happens to be scrolled: open both and only the appended one survives the box.

virtualize

Both fields hold the same 10 000 options. The windowed one keeps about twenty rows in the DOM whatever you scroll to; the eager one builds all 10 000 to show six. Off by default and never switched on at a row count — Ctrl+F finds only the rendered rows, and CSS targeting :last-child matches the last rendered row. aria-setsize still carries the real list either way. Note what "select all" means here: the visible options are the whole filtered list, not the rendered window, so it selects all 10 000.

panel and options

The panel exists only while it is open, so each line below reads "no element matches" until its own field is opened — then it fills in and follows it. The list is a single tab stop: the arrow keys move between rows, Home and End jump to the ends, Enter toggles a row without closing the panel, and Escape closes it.

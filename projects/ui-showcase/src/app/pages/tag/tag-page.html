size × variant

Every surface — the fill, the border, the text — is mixed from one colour per variant, so the four read as one family in every theme. The colour is a hint, never the message: the text has to say "Paid" or "Overdue" on its own, for anyone who cannot tell green from red.

iconName takes any built-in or registered name; the gogTagIcon template (the third tag) replaces it with any markup, and wins when both are set. The icon is sized from the tag's own scale, not from --gog-icon-size.

width

A tag fits its text and never wraps: two words of a status splitting across lines reads as two tags. fullWidth stretches it across its container instead, text centred. Text longer than the room it gets ends in an ellipsis inside the border — until 21.15.0 it ran out through it, as the third tag would have. The cut text is still read in full by a screen reader, but a sighted reader loses it, so keep a status short or show the whole of it somewhere else.

--gog-tag-accent — a colour outside the four

The four variants cover status. For a category — a team, a label colour a user picked — set --gog-tag-accent on the tag and the fill, border and text are all derived from it the same way. Check the contrast of a colour you bring: the library's own four are measured in every theme, and yours is not.

host and icon attributes

Read from the live DOM. The host carries no ARIA at all, so a screen reader reads the tag's text where it stands, as it would any span. The icon is aria-hidden whichever way it was given — so an icon cannot be the only thing that says what a tag means. A tag that must interrupt, like a status that changes while the page is open, needs a live region around it; gog-alert is the component for a message that has to be heard.

tag, chip or badge

A tag labels something and does nothing when pressed. A chip is something to press, toggle or remove. A badge is a count pinned to the corner of another control. If a tag starts needing a click handler, it has become a chip.

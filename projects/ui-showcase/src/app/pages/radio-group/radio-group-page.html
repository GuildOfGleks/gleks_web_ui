size × state

The circle, the dot and the option labels scale from the --gog-control-checkbox-* lengths that gog-checkbox reads too, so a radio and a checkbox of one size line up on a form. A disabled group fades once, as a whole, label and error included; Enterprise is disabled by its own disabled: true and fades by the same amount inside a group that is not.

orientation × fullWidth, in a 28rem container

fullWidth makes every option as wide as the group, so the whole line is the hit target. In a horizontal group that means the options share the row in equal parts — they stay a row, and wrap only once the labels no longer fit. (Until 21.15.0 the last row here came out as a vertical list: each option took the full width and wrapped onto a line of its own.)

options — a fixed shape

Options are {{ '{' }} id, label, disabled? {{ '}' }} and nothing else: there is no optionLabel / optionValue accessor as on gog-select, so a domain list is mapped into that shape first. The id is the value, and it keeps its type — the second group uses numbers and hands back a number. A long label wraps beside its circle rather than pushing it out of line.

a group with no visible label

ariaLabel names the group when the surrounding UI already says what it is. With a label set it is ignored: the visible text names the group through aria-labelledby instead.

[(value)], and the keyboard

The options are native <input type="radio">s sharing one name, so the keyboard is the platform's: the group is a single Tab stop, and the arrow keys move and select in one step, skipping the disabled option. A press on the selected option changes nothing — a radio group cannot be emptied by the user, only by writing null to it, which the button below does. A value that matches no option selects nothing and is kept as it is.

value: {{ bound() | json }} · {{ count('bound') }} valueChange

The second button writes the id of the disabled option: the component shows it selected, because disabled on an option stops the user from choosing it, not the model from holding it.

formControl, errorDisplay="auto"

Tab into the group and out again without choosing anything: the control decides the error timing from its own touched and invalid state, and a choice clears it. Before 21.15.0 this mode never showed anything on a radio group — it was the one control that did not read the form's state back.

value: {{ formControl.value | json }} · touched: {{ formControl.touched }} · disabled: {{ formControl.disabled }}

name

Unset, every group generates its own, which is what keeps two groups on one page apart. Set it only when a native <form> submission needs a particular field name — and never give two groups the same one: the browser would treat their options as a single group and uncheck one group's option when the other is pressed, behind both components' backs.

group attributes

Read from the live DOM. The group is named by its visible label through aria-labelledby, or by ariaLabel when there is none; an error ties itself on with aria-describedby and flips aria-invalid. A disabled group has no attribute of its own — the disabled state lives on each option's input, below.

option input attributes

Each option is a <label> around its input, so its text is its accessible name. The selected option is the input's checked property, set by the component and never written as an attribute, which is why it does not appear here — it is what the screen reader announces all the same. The circle is a span and is not focusable; the input under it is.

when to reach for this and when for something else

A radio group is one answer from a short list that is all worth seeing at once. Past five or six options it is a gog-select; for a choice that reads as a view switch — a segmented control in a toolbar — it is gog-button-toggle-group, whose single mode is a radio group too, with the arrow keys moving and selecting the same way.

Custom cell & header templates

Any column can swap its default text rendering for a template projected into that column — gogColumnBody for cells, gogColumnHeader for the header. The body context gives you let-row (also $implicit), let-value for the already-resolved cell value, and let-i="index".

Full width

Full width of its container by default (see every table above). [fullWidth]="false" shrinks the table to fit its columns instead — useful for a narrow, two-column table that shouldn't stretch to fill a wide page.

Server-driven (lazy) & selection

[lazy]="true" hands sorting and paging to the server: the table renders value exactly as given, never re-orders or re-slices it, and asks totalRecords how many pages exist. Sorting a header or moving the paginator fires gogSortChange / gogPageChange — those are the refetch signals. This demo talks to a fake 137-row endpoint with a 350 ms delay.

dataKey="id" is what keeps the selection alive across pages and refetches — the table matches rows by that field instead of by object identity, so the boxes you ticked on page 1 are still ticked when you come back to it. The header checkbox covers the current page, never the pages the client has not seen.

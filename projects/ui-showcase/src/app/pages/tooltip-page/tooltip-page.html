gogTooltip

Tooltip

Not a component — an attribute directive you drop onto anything: a gog-* component's own host tag, or a plain native element. It renders a small hover/focus hint, appended to document.body so it's never clipped by an ancestor's overflow: hidden. 

<button gogTooltip="Save changes">Save</button>

<gog-chip [gogTooltip]="'Assigned to Aeliana'">AK</gog-chip>

Styling one instance

The bubble is appended straight to document.body, outside any component's own view — so a --gog-tooltip-* override scoped to some wrapper around the trigger (a page's own stylesheet, an ::ng-deep) never reaches it, only a :root-level one does. To restyle a single instance, gogTooltipClass puts a class straight onto the bubble itself; the class still has to live in an unscoped stylesheet (a global styles.scss, not a component's own) for the same reason. See .showcase-tooltip--brand in this app's styles.scss.

Content & sizing

No default cap on height — a hint is meant to read as a short paragraph, not a scrollable panel, so it just wraps to --gog-tooltip-max-width (280px by default) and grows as tall as it needs. A single unbroken run of characters longer than the max-width still breaks mid-word instead of overflowing it.

Long paragraph One long unbroken word Narrower max-width Capped height + scroll

"Capped height + scroll" adds a plain max-height + overflow-y: auto through the same gogTooltipClass mechanism — not a library feature, since most hints shouldn't need it, but there's nothing stopping a consumer who wants it for one unusually long tooltip. To actually scroll it: move the mouse from the button down into the bubble before it closes. The bubble is hoverable (WCAG 2.1 SC 1.4.13) — moving the pointer onto it cancels the pending hide the same way re-entering the trigger would, so it stays open (and scrollable) for as long as the pointer is over either one.

Every environment its own approval chain:

1. A merge to main queues a build and deploys to staging automatically.

2. Staging soak time is 30 minutes minimum before production is even offered.

3. Production requires sign-off from a workspace admin, logged with a reason.

4. Rollbacks go through the exact same approval step as a forward deploy.

Global defaults

gogTooltipPosition, gogTooltipShowDelay and gogTooltipHideDelay all fall back to GOG_CONFIG.tooltip when left unset on an instance, the same as every other configurable input in the library — see the Global Config page. Without it connected, as on this page, they use their own built-in defaults: 'auto', 300ms and 100ms.

Performance limits

How @guildofgleks/ui actually behaves at scale — not "will it work", but "what does 500,000 or 1,000,000 of this cost, in this browser, on this machine". Every page here builds real data, hands it to a real component, and times from that hand-off to the next actual paint (two requestAnimationFrame ticks, not a framework-internal counter) — the same wall-clock delay a user would feel.

"Prep" is building the data itself — an array of plain objects, the caller's own cost, not the library's. "Render" is what the component does with it. Large counts are gated behind an explicit confirmation: this is deliberately trying to find the point where a tab freezes, and there's no cancelling once a synchronous render that size has started.

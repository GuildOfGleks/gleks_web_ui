gog-card

Card

A surface for one self-contained thing. What it adds over a .card class of your own is what a class cannot do: it takes its accessible name from the projected gogCardHeader heading, it folds in loading and disabled, and gogCardLink makes the whole surface activate a real link — your <a>, with your routerLink still on it.

Variants

outlined is the default: a border and no shadow, which is what a grid of many wants. elevated takes the shared surface shadow — the same one dialogs and dropdown panels use. filled is a tint, neither border nor shadow.

@for (variant of variants; track variant) {

{{ variant }}

}

Interactive — the whole surface activates one real link

No interactive input: the card becomes interactive because it holds a gogCardLink. The link below is an ordinary routerLink, so middle-click, "open in new tab" and the keyboard all behave the way they do anywhere else — and the footer button still receives its own clicks instead of the card's link swallowing them.

Loading and disabled

loading swaps the content for placeholders shaped like a title and body copy, and marks the host aria-busy — the region treatment, not a spinner. disabled dims the card and takes its link out of the tab order: Tab past the pair below and only the enabled one stops.

{{ loading() ? 'Finish loading' : 'Load again' }}

Theming

Every value comes from a --gog-card-* token, and the instance tier (--gog-card-bg, --gog-card-border-color, --gog-card-shadow, --gog-card-padding-y, --gog-card-padding-x, --gog-card-gap) is undeclared on purpose, so setting one on an element beats the variant and size classes without a specificity fight.

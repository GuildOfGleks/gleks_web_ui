GOG_CONFIG

Global Config

A handful of component inputs are things a whole app wants to set once — how aggressively gog-button debounces clicks, how long a gog-scroll thumb stays visible before fading, how long gogTooltip waits before showing or hiding — instead of repeating on every instance. GOG_CONFIG and provideGogConfig(...) are the library's one place to do that.

Connecting it

Call provideGogConfig(...) once, in your app's root providers — typically app.config.ts: 

// app.config.ts
import { ApplicationConfig } from '@angular/core';
import { provideGogConfig } from '@guildofgleks/ui';

export const appConfig: ApplicationConfig = {
  providers: [
    provideGogConfig({
      button: { debounce: 1500 },
      ripple: { enabled: true },
      scroll: { autoHide: false },
      tooltip: { showDelay: 800, hideDelay: 400, position: 'bottom' },
      floatLabel: { variant: 'in' },
      control: { size: 'lg', errorDisplay: 'auto', clearable: true },
      dropdown: { appendToBody: true, filter: true, filterPosition: 'bottom' },
      datepicker: { locale: 'ru-RU', firstDayOfWeek: 1, format: 'dd.MM.yyyy' },
      autocomplete: { searchDebounce: 1000, minLength: 2, openOnFocus: false },
      inputfield: { showSpinButtons: false },
      textarea: { resize: 'both' },
      toast: { position: 'top-left', duration: 1500 },
    }),
    // ...your other providers
  ],
};

Every gog-button, gog-scroll, gogTooltip, floating- label-capable field, gog-select/gog-multiselect, gog-datepicker, gog-autocomplete, gog-inputfield and gog-textarea in the app then picks up those defaults automatically — no per-instance inputs needed. An instance's own input, when set, still always wins over the global config; this only fills in what the instance didn't specify itself. Providing it again further down the tree (a route, a single component's own providers, as the section below does) replaces the whole object for that subtree instead of merging with the parent's. (toast is the one exception — see the dedicated section near the bottom of this page.)

Without it connected — library defaults

This showcase app's own app.config.ts does not call provideGogConfig anywhere, so everything on this page falls back to each component's own hardcoded default: gog-button debounces at 300ms, gog-scroll fades its thumb after ~800ms, gogTooltip shows after 300ms, hides after 100ms, and picks its own side ('auto'), and fields keep their static label above the box (floatLabel: 'none'). Nothing breaks — the components are fully usable with zero configuration; you just get their built-in defaults everywhere.

With it connected

<app-global-config-scope> below has the same call as the code sample above (minus toast) in its own component providers — scoped to one subtree instead of the whole app, so this page can show both side by side. Click both buttons rapidly for a couple of seconds and compare the accepted-click counts; the scroll thumb here also never fades; the tooltip button takes noticeably longer to show/hide and always opens below; the email field's label floats instead of sitting statically above it; the role select is bigger, offers a search box, and portals its panel to <body>; the date field shows Russian month names, starts weeks on Monday, and formats as dd.MM.yyyy; the city field waits a full second after you stop typing and needs two characters before it searches, and no longer opens just from focusing it; the amount field's custom spin buttons are gone; and the notes field's drag handle resizes in both directions instead of only vertically.

toast — the one section that can't be demoed the same way

ToastService is providedIn: 'root' and reads GOG_CONFIG exactly once, at construction, from the root injector — a component-scoped provideGogConfig({ toast: {…} }) the way <app-global-config-scope> uses for everything else above would silently never reach it, because the service instance already existed (and already resolved its config) before that scoped provider was ever in the picture. toast can only be set where a real app would set it: once, in the true root providers.

This showcase's root providers don't call provideGogConfig at all, so the button below shows the library's own built-in default — bottom-right, 4000ms. A toast: { position: 'top-left', duration: 1500 } in app.config.ts would move and shorten every toast the whole app shows, this one included.

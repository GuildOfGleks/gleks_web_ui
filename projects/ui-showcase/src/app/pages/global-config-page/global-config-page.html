GOG_CONFIG

Global Config

A handful of component inputs are things a whole app wants to set once — how aggressively gog-button debounces clicks, how long a gog-scroll thumb stays visible before fading — instead of repeating on every instance. GOG_CONFIG and provideGogConfig(...) are the library's one place to do that.

Connecting it

Call provideGogConfig(...) once, in your app's root providers — typically app.config.ts: 

// app.config.ts
import { ApplicationConfig } from '@angular/core';
import { provideGogConfig } from '@guildofgleks/ui';

export const appConfig: ApplicationConfig = {
  providers: [
    provideGogConfig({
      button: { debounce: 1500 },
      scroll: { autoHide: false },
    }),
    // ...your other providers
  ],
};

Every gog-button and gog-scroll in the app then picks up those defaults automatically — no per-instance inputs needed. An instance's own input, when set, still always wins over the global config; this only fills in what the instance didn't specify itself. Providing it again further down the tree (a route, a single component's own providers, as the section below does) replaces the whole object for that subtree instead of merging with the parent's.

Without it connected — library defaults

This showcase app's own app.config.ts does not call provideGogConfig anywhere, so everything on this page falls back to each component's own hardcoded default: gog-button debounces at 300ms, gog-scroll fades its thumb after ~800ms. Nothing breaks — the components are fully usable with zero configuration; you just get their built-in defaults everywhere.

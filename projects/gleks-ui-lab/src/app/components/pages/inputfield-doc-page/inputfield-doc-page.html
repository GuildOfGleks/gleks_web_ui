gog-inputfield

Input Field

A text field with five sizes, leading/trailing icons that can double as buttons, a built-in password reveal toggle, and full ControlValueAccessor support.

Overview

Import the component and drop it into a template.

Basic usage — a labelled field bound with [(value)]. The value is the string in the field; valueChange fires on every keystroke.

Examples

Sizes

Five steps, also settable app-wide through GOG_CONFIG.control.size.

States

Default, disabled, readonly and with an error. readonly keeps the field focusable and its text selectable; disabled takes it out of the tab order and dims the whole field — label, box, icons and addons — as one piece .

Types

type is forwarded to the native input, so each of these brings the browser's own keyboard, validation and pickers — the date and time types render the native picker. password and number gain the library's own controls, below.

Icons

iconStart / iconEnd take a bare icon name — the common case, and the whole API for a decorative icon: it renders an aria-hidden span, never a button.

Addons

For anything more than an icon name, project a gogInputAddonStart or gogInputAddonEnd element. Because it takes arbitrary markup, an actionable addon is a real <button> with its own aria-label and (click) — nothing threaded through the field. The field measures each addon and makes room for it , so a wide one like https:// no longer runs under the typed text.

Clearable

The built-in clear button is value-driven: it appears once there is something to clear and goes when there is not — replacing the hand-rolled trailing-icon-plus-callback pattern.

Password

type="password" gets a show/hide toggle; its icon and accessible label switch with the state. The toggle keeps the outer edge, and an iconEnd or a gogInputAddonEnd renders beside it — before, either was silently dropped.

Number — the stepper

A type="number" field draws the library's own +/−, so they follow the theme and are the same size in every browser; at min or max the button for that direction is disabled. [showSpinButtons]="false" removes them, and the field still steps with the arrow keys and the wheel — that is native behaviour. clearable and the stepper coexist: the clear button sits inside the stepper and the gutter widens for both.

Number — beside the stepper

The stepper keeps the outer edge, and an iconEnd or a unit addon sits beside it . The clear button still takes that place while there is a value to clear, as on every field.

Number and date values

Through a formControl a number field's value is a real number (null when empty). [(value)] always hands back the string in the field — for a date, the native yyyy-MM-dd.

Float label

floatLabel rests the label inside the field like a placeholder and floats it on focus or once there is content. in stays inside the border, on centres on the top border, over floats fully above — each shown empty, then with a value. floatLabelShowPlaceholder brings the placeholder back under the floated label.

Error message

errorDisplay="manual", the default, shows errorMessage for as long as it is non-empty — you own the timing. Type one or two characters.

Reactive forms

Wire it with [formControl] instead of [(value)]. With errorDisplay="auto" the error shows once the control is touched and invalid — leave the empty field to see it. Disabling the control disables the field.

Width

Fields fill their container by default — the dashed box here. [fullWidth]="false" shrinks the field to a text input's own width.

App-wide defaults — GOG_CONFIG

control.size, control.clearable and floatLabel.variant set the defaults for every field under the provider; an instance's own input still wins. In an app the provider goes in app.config.ts — see Global Configuration.

Accessibility

gog-inputfield renders a native <input> wired to its <label>, so the platform supplies the role, the keyboard and the name.

  • Name — label. A field with no visible label of its own takes your <label for> through inputId; there is no ariaLabel input, so a nameless field cannot be shipped by accident.
  • Error — errorMessage sets aria-invalid="true" and links the message with aria-describedby.
  • Input hints — inputMode, autocomplete and spellcheck are forwarded to the native input.
  • Its own buttons — the stepper, clear and reveal buttons are named by incrementLabel, decrementLabel, clearAriaLabel and the show/hide labels, or GOG_CONFIG.labels. A stepper button at its bound is disabled.

Test hooks

The field's own buttons carry data-gog-part — increment, decrement, clear and password-toggle — so a test or an automation script can find them with [data-gog-part="clear"]. Prefer it to the internal gog-input__* classes, which may change.

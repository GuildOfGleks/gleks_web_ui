gog-radio-group

Radio Group

An options-driven radio control — the radio counterpart to Checkbox. It renders native <input type="radio">s sharing one group name, so mutual exclusivity and arrow-key navigation come from the browser rather than from roving-focus code.

Examples

States

Empty, holding a value, a disabled group, and an error — each with Enterprise disabled on its own, so the option-level and the group-level disabled can be read side by side. A disabled group fades once, as a whole ; before, its options faded twice.

Sizes

Five steps. The circle, the dot and the labels scale from the --gog-control-checkbox-* lengths gog-checkbox reads too, so a radio and a checkbox of one size line up on a form.

Orientation and full width

vertical by default; horizontal for two or three short options. fullWidth makes every option as wide as the group, so the whole line is the hit target — and in a horizontal group the options share the row in equal parts, wrapping only once the labels no longer fit . Before 21.15.0 that last group came out as a vertical list.

Option ids and long labels

The id is the value and keeps its type: the first group uses numbers and hands back a number. A long label wraps beside its circle rather than pushing it out of line.

No visible label

ariaLabel names the group when the surrounding UI already says what it is. With a label set it is ignored: the visible text names the group through aria-labelledby.

Two-way binding

value is a model. A press on the selected option changes nothing — a radio group cannot be emptied by the user, only by writing null to it. The second button writes the disabled option's id, and the group shows it selected: disabled on an option stops the user choosing it, not the model holding it. A value that matches no option selects nothing and is kept as it is.

Reactive forms and validation

A ControlValueAccessor. With errorDisplay="auto" the message appears once the control is invalid and touched — tab into the group and out again without choosing — and a choice clears it. Before 21.15.0 this mode never showed anything on a radio group : it was the one control that did not read the form's state back.

App-wide defaults — GOG_CONFIG

control.size sets the default size; control.errorDisplay reaches this component too, so an app that wants every control on 'auto' sets it once. An instance's own input still wins. See Global Configuration.

Options — a fixed shape

Each option is a GogRadioOption. value holds the selected option's id rather than the object itself, since a radio group is a single-value control bound straight to a form field. There is no optionLabel / optionValue accessor as on Select: a domain list is mapped into this shape first.

Accessibility

A role="radiogroup" container around native radios sharing one name: the group carries the name and the error, and each option's role, state and keyboard come from the platform — there is no roving-focus code here.

  • Keyboard — the group is one tab stop; the arrows move and select, skipping disabled options.
  • Name — the visible label through aria-labelledby, or ariaLabel when there is none. Each option is a <label> around its input, so its text is its name.
  • Error — aria-invalid on the group and an aria-describedby pointing at the message.
  • name — unset, every group generates its own, which keeps two groups apart. Set it only for a native form submission, and never give two groups the same one: the browser would treat their options as one group behind both components' backs.

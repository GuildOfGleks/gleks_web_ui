gog-scroll

Scroll

A drop-in replacement for a native overflow: auto region. Content keeps scrolling natively — wheel, touch, keyboard, focus-into-view all still work — only the browser's own scrollbar chrome is hidden and replaced with a themeable, draggable overlay thumb.

Overview

Import the component and give it a height (or width).

Basic usage — gog-scroll scrolls whatever does not fit the box its host is given, so the height is set on the element. Leave the host's display alone: it is a flex column, and that is what carries the height down to the viewport.

Examples

Size and auto-hide

size="thin" shrinks the track and thumb. With autoHide on (the default) the thumb shows while the region is scrolled or the pointer moves over it, and fades hideDelay ms later; off, it stays. Hover, drag and the track's own hover are live.

Axis

vertical (the default), horizontal or both — which axes get a thumb. The other axis is not scrollable at all: vertical clips horizontal overflow rather than scrolling it natively.

No track — showTrack

[showTrack]="false" removes the thumb and the track while the region still scrolls by wheel, touch, keyboard and script — for a viewport whose position is driven some other way, the way gog-tabs drives its header row. Settable app-wide via GOG_CONFIG.scroll.showTrack.

Horizontal wheel

Hover the first row and turn the wheel: the page moves. A vertical wheel over a region with nothing to scroll vertically belongs to the browser, and this component draws its thumb over native scrolling rather than replacing it, so that is the default and always was. [horizontalWheel]="true" is the opt-in exception — the second row is the same markup with that one input.

What it does not do is the part worth reading. Scroll the second row to its right-hand end and keep turning: the page starts moving again. The translation only happens while there is room left in the direction of the turn, so a region can never swallow the wheel and leave the page feeling stuck — which would be a worse bug than the one this fixes. It also keeps out of the way of anything that already works: a trackpad's sideways swipe and Shift+wheel carry a horizontal delta the browser applies correctly, Ctrl+wheel is pinch-zoom, and a region that can still scroll vertically is left alone — so axis="both" keeps scrolling down while there is down to go.

Off by default, because it changes what an existing region does with a gesture it currently passes on. GOG_CONFIG.scroll.horizontalWheel turns it on app-wide.

Overscroll

overscrollBehavior is the CSS property: contain keeps a scroll that reaches the region's end from moving the page behind it, which is what a dropdown or a side panel wants. Scroll each to its end and keep going.

Reach events

gogReachStart / gogReachEnd fire once per crossing, within reachThreshold pixels of the edge; gogScroll emits live metrics on every scroll and resize.

Scroll methods

Grab the instance with viewChild and call scrollToTop / scrollToBottom / scrollToLeft / scrollToRight / scrollTo directly.

App-wide defaults — GOG_CONFIG

size, autoHide, hideDelay and overscrollBehavior default to undefined so they can fall through to an app-wide (or subtree-wide) default set once via provideGogConfig(...), instead of repeating the same inputs on every instance. An instance's own input, when set, always wins.

Accessibility

Scrolling stays the browser's, so everything a native region does for assistive tech it still does; the thumb and track are empty pointer affordances on top.

  • Tab stop — while its content overflows, the viewport is a tab stop with role="region", per the WAI-ARIA scrollable-region pattern, so the arrow keys, Page Up / Page Down and Home / End scroll it. With nothing to scroll the stop, the role and the name go away, since a dead stop helps no one.
  • Name — ariaLabel names that region. A region that scrolls with no name logs one console.warn per page in dev mode , never in production — checked when the region appears, so a viewport that never overflows never warns. A gog-table names its own scroll through its ariaLabel.
  • Nested — set focusable to false inside a component that already owns focus, such as a listbox panel or a dialog body, so it adds no redundant stop. Focus moving into content still scrolls it into view either way.

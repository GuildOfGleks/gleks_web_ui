gog-spinner

Spinner

A branded loading indicator with two built-in animated variants, fully custom-content support, size variants, per-instance color and speed overrides, and both a content-scoped and a full-screen overlay mode.

Sizes and variants

runic is the default and the library's own; ring is the plain one. custom projects your markup into the same size box, so it scales like the other two — the third column projects an SVG that animates without a stylesheet. Under prefers-reduced-motion the built-ins stop moving and stay drawn; a custom one is yours to stop.

Animation speed

--gog-spinner-spin-duration (and -pulse-duration for the rune glow) retime the built-in animations per instance without swapping variant — to signal urgency, or to match a surrounding motion rhythm.

Colour

The spinner draws in the accent colour. On a surface where the accent does not read — a danger banner, a filled button — set --gog-spinner-color on it or an ancestor.

The app's own indicator, everywhere at once

Most of the spinners an app shows are not ones it writes: gog-button draws one while loading, gog-autocomplete while it searches, gog-table in place of its rows, gog-spinner-overlay over a region — none take a spinner input. GOG_CONFIG.spinner.component gives them your look: pass a component, and every spinner the library draws renders it inside its own size box, keeping the sizing and the accessible name. Here a pulsing skeleton bone stands in for your loader, so the example carries no stylesheet. An instance's own variant still wins; GOG_CONFIG.spinner.variant is the lighter key, choosing between runic and ring app-wide. See Global Configuration.

Covering a region

gog-spinner-overlay

Lays a scrim and a spinner over its own content while loading is on, and marks the region aria-busy. The content stays rendered underneath, so nothing jumps when loading ends. The scrim stops the pointer and the content is inert , so Tab skips it too; focus that was inside — press Export, then load — waits on the spinner and comes back when loading ends. It forwards variant, size and ariaLabel to its spinner.

The whole viewport

overlay on gog-spinner itself covers the viewport, for a load that blocks the whole app. "The viewport" holds only while no ancestor creates a containing block: a transform, filter or contain above it retargets the overlay to that element, so render it near the app's root. On this site it covers the content area rather than the window — that area is a gog-scroll, which sets contain: layout style.

Accessibility

An indeterminate progress bar named by ariaLabel. It does not announce itself — the region that is busy does, with aria-busy.

  • Role and name — role="progressbar" with no value, the pattern for "working, no idea how long", named by ariaLabel . Name it for what is loading when more than one thing can be; ariaLabel="" makes it decorative.
  • Inside a loading gog-button it is aria-hidden, because the button already says it is busy.
  • Regions — gog-spinner-overlay sets aria-busy on the region it covers and makes its content inert while loading.
  • Keyboard — none. A spinner is not focusable.

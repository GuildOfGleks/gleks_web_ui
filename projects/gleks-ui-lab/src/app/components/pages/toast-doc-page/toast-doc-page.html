gog-toast

Toast

Fire-and-forget notifications via ToastService, rendered by a positioned gog-toast-container — with per-corner stacking, action buttons, sticky and timed variants, and automatic deduping of repeated calls.

Overview

Import ToastContainerComponent and mount <gog-toast-container /> once, near the root of the app. Every ToastService call renders through that one outlet, however many places call it.

Examples

Types and states

The type picks the edge colour and the glyph. A timed toast carries a progress bar counting down its duration; one queued behind the front of its stack ([isFront]="false", the third in each type) keeps the bar full and still. These are placed directly to show every state at once — an app never places a gog-toast itself; the container renders one per show().

Long messages and icons

The toast is at least --gog-toast-min-width wide and caps itself in ch of its own message font, against the viewport too; the message wraps and the actions go under it. iconName replaces the type's glyph — any built-in, or a name registered with provideGogIcons; iconTemplate takes any markup. The colour stays the type's.

Fully configurable

Every field feeds one show() call — message, type and position are all the caller's.

Types, positions and the stack

Each corner is its own stack, oldest in front. Only the front toast counts down; the ones behind wait with a full bar and fan out on hover. Past the container's maxVisiblePerPosition (5 on this site) the rest queue out of sight and are not announced until they are shown.

Duration and sticky

duration overrides the 4000 ms default; isSticky disables auto-dismiss entirely. dismissAll() clears every corner.

Actions, show() and dismiss()

An action's onClick gets the toast; pressing one does not close it, so an Undo calls dismiss(toast.id) itself. show() and the four shorthands return that id.

dedupeKey

A show() whose dedupeKey matches a toast still open replaces it in place — new message, timer restarted, announced again — instead of stacking another. Unset, the key is derived from the message, type, icon, position and action labels, so the same toast fired twice is one toast; this button changes its message each time, so it names a key.

App-wide defaults

GOG_CONFIG.toast.position and .duration set the corner and the time for every toast; a show() call still overrides them. They are read once, by the root ToastService, so they belong in app.config.ts — a provideGogConfig lower down never reaches them. labels.closeToast names the close button. See Global Configuration.

Accessibility

A toast carries no role or aria-live. The container owns two live regions, mounted before any toast exists, and copies each shown toast's message into one.

  • Announcements — one region is polite, one assertive; the toast's type picks which (assertive for error and warning, polite otherwise). A live region has to exist before the text lands in it to be announced at all, which is why the toasts do not carry their own. The message leaves the region when the toast does.
  • Queued toasts past maxVisiblePerPosition are not announced until they are shown.
  • Keyboard — the close button and the actions are real buttons in the tab order. The close button is named by GOG_CONFIG.labels.closeToast.
  • Timing — hovering a toast pauses its countdown. Under prefers-reduced-motion the progress bar still reports the time left, in twenty discrete steps rather than a slide. Put anything a user must act on in a sticky toast or somewhere that does not expire.

gog-select

Select

A single-choice dropdown over your own objects: a button trigger, a listbox panel that can filter, virtualize and escape a clipping container, and full ControlValueAccessor support. For several choices see Multiselect; for a typed query, see Autocomplete.

Sizes

Five steps, also settable app-wide through GOG_CONFIG.control.size.

States

Empty, holding a value, disabled and with an error. With the default errorDisplay="manual" the message shows for as long as errorMessage is non-empty — the timing is yours; see Reactive forms below for the automatic kind.

Clearable

The clear button appears only once something is selected, so a field no longer needs a fake "— not selected —" option to make a choice undoable. It takes the outermost trailing position and the chevron shifts inward. It is the one part of the trigger that is not the trigger: a button inside a button is invalid HTML, so it is a sibling laid over the trigger's end edge, named by clearAriaLabel. Off by default here — Multiselect is the one control where it is on.

Width

A field fills its container by default — the dashed box here. With [fullWidth]="false" the trigger sizes to whatever is selected, so a short option collapses it; minWidth is the floor under that.

Custom chevron, and no visible label

gogDropdownChevron replaces the chevron. The library turns only its own; a custom one gets let-open and draws the state itself — open the first field to watch the glyph change. ariaLabel names a field that has no label.

Your own objects

optionLabel, optionValue and optionDisabled each take a property path — dot-paths included — or a function, so a real DTO goes in with no mapping into {{ '{' }} id, name {{ '}' }} first. [optionValue]="null" makes the value the option object itself, the same reference that went in. A gogDropdownOption template replaces one row, and its context carries the resolved label; [gogDropdownOptionTypeOf] types the option, so a typo in option.profile.role fails the build.

A disabled option

optionDisabled defaults to the disabled property, so a GogDropdownOption carrying it needs no binding. The row stays in the list, is announced as disabled, and neither the pointer nor the keyboard selects it.

Filtering

filter puts a search box in the panel — worth it past about seven options, or order them instead, since a list the reader can predict is one they search rather than choose from. The default matcher is a case-insensitive substring of the resolved label; filterMatch swaps in any predicate. The query resets when the panel closes. The search box has square corners, and that is the concentric answer: inset from the panel edge by exactly the panel's radius, its corner sits on the centre of the panel's corner arc, the one shape that keeps the gap constant. Override --gog-select-panel-radius and it reshapes to match.

Direction

'auto' measures the room under the trigger and flips up when there is not enough; 'down' and 'up' are fixed, whatever the viewport does.

The panel — appendToBody

The panel renders inline by default and is clipped by any scrolling or overflow: hidden ancestor; open the first two — only the appended one survives its box. dropdownWidth and dropdownMaxHeight take any CSS length and apply only while the panel is appended: the third holds 20 options in 160px, so it scrolls.

Virtualized options — virtualize

Both fields hold 10 000 options. Open each and compare how long the panel takes to appear: the windowed one keeps about twenty rows in the DOM, the eager one builds all 10 000 to show six — measured in Chrome, 512 ms against 21 ms. The scrollbar looks the same either way, because spacers stand in for the missing rows.

Off by default, and never switched on at a row count. Ctrl+F finds only the rendered rows, and CSS targeting :last-child matches the last rendered one; a threshold would make that depend on how much data arrived. Set it per field, or app-wide with GOG_CONFIG.dropdown.virtualize. The announced count stays honest — aria-setsize carries the real list — and scrolling a focused row out of view hands focus back to the trigger, since the row no longer exists. gog-table's virtualize works differently under the same name: see the Table page.

Float label

'none' keeps the label above the field; 'in', 'on' and 'over' rest it inside the trigger until focus or a selection moves it clear — each shown empty, then with a value. floatLabelShowPlaceholder brings the placeholder back under the floated label.

Reactive forms

With errorDisplay="auto" the error shows once the control is touched and invalid — open the panel and close it without choosing — instead of the page computing when to pass an errorMessage. A choice clears it.

App-wide defaults — GOG_CONFIG

control.size, control.clearable, dropdown.filter and floatLabel.variant set the defaults for every field under the provider; an instance's own input still wins. Open the third field for the filter. In an app the provider goes in app.config.ts — see Global Configuration.

Accessibility

The trigger is a native <button>, not a <select>, carrying aria-haspopup="listbox", aria-expanded and aria-controls; the panel is a role="listbox" of role="option" rows with aria-selected and aria-disabled. The panel exists only while it is open.

  • Keyboard — on the trigger, Enter or Space opens and closes the panel; while it is open ↓ / ↑ move into the list on the first or last option. In the list the arrows move, wrap and skip disabled options, Home/End jump to the ends, Enter or Space selects, Esc closes and returns focus to the trigger, and Tab closes and moves on from the trigger — so an appended panel does not send focus to the end of the document. The list is one tab stop. Inside a dialog, Escape closes the list first and the dialog on the next press.
  • Name — the label through aria-labelledby, because a button is not a labelable element and for would be ignored. Without a label, ariaLabel, then the placeholder. The clear button is named by clearAriaLabel.
  • Error — aria-invalid on the trigger and an aria-describedby pointing at the message, which is a role="alert".
  • Virtualized — aria-setsize and aria-posinset carry the real list, so a screen reader hears "10 000 items", not "20".

gog-calendar

Calendar

The month grid behind Datepicker, exported and usable on its own for an always-visible calendar. Native Date throughout — no date library and no adapter abstraction, so the package keeps its zero runtime dependencies.

Overview

Import the component and drop it into a template.

Import it from @guildofgleks/ui/datepicker, together with gog-datepicker. The root package has not exported it since 21.14.0 — in 21.13.0 it still did, deprecated — and that is what lets a calendar used only behind a lazy route keep its own code out of your app's initial bundle. What it imports from the root does not move: the icons it draws belong to the root package, and load wherever your first page already loads it. Measured on a fresh app with the table, datepicker, calendar and dialog behind one lazy route: the initial bundle went from 101.2 kB to 88.2 kB, and 27 kB of those components' root dependencies stayed in it.

Basic usage — [(value)] holds a Date. The grid always renders six weeks, so its height never changes as you page through months: a calendar that grows and shrinks by a row shifts whatever sits under it, and inside a dropdown panel moves the panel itself.

Range, and the two outputs

In range mode the value is a {{ '{' }} start, end {{ '}' }} pair, and two months side by side is what makes picking one practical. The two outputs are not the same event: valueChange fires for every change, including the first press of a range; gogDateSelect fires only when the selection is complete — a day in single mode, both ends in range mode. That is the one gog-datepicker closes its panel on.

Bounds and disabled dates

min and max cover the bounded case — days outside them are disabled, not hidden. disabledDates is a predicate, not an array: "weekends" and "public holidays" have no finite list a consumer could hand over without materialising every date in range first.

Time

showTime adds a clock under the grid; hourFormat, minuteStep and showSeconds configure it. The value stays a single Date, carrying the time.

The two footer buttons

Deliberately two controls, not one. Today selects today's date; This month only moves the view back and leaves the selection alone. One button doing both read as "take me back" to one person and "set it to today" to another, and no wording fixed that. Where min or disabledDates rule today out, Today is disabled rather than silently doing nothing.

Locale

Month and weekday names come from Intl, so any BCP-47 tag works with no data to ship. firstDayOfWeek overrides the locale's own choice.

The nine labels

Every string the calendar renders is an input — the two footer buttons, the four navigation arrows and the three time fields — and each falls back to GOG_CONFIG.labels, then to English. Inspect the arrows: their accessible names are German too. gog-datepicker takes the same nine and hands them to its calendar.

Width in a block container

The grid caps itself at its own width: --gog-calendar-max-width is max-content by default and follows numberOfMonths, showTime and the size steps on its own. Each calendar here is as wide as the card, so without the cap the header would spread across while the days huddled at the start. Set it to 100% for a calendar that fills its container.

App-wide defaults — GOG_CONFIG

A standalone calendar resolves locale and firstDayOfWeek from GOG_CONFIG.datepicker itself, and its labels from GOG_CONFIG.labels — no datepicker involved. An instance's own input still wins. In an app the provider goes in app.config.ts — see Global Configuration.

Accessibility

The days follow the ARIA grid pattern, and all 42 cells share one tab stop, so tabbing past the calendar does not mean 42 presses. The navigation arrows are buttons named by their labels.

  • Keyboard — the arrows move by a day and a week, Home/End to the ends of the week, PageUp/PageDown by a month and with Shift by a year, Enter or Space picks.
  • Focus follows the highlight — the arrows move the focus ring and not only the roving tabindex, so a screen reader announces each day as it is reached.
  • Disabled days — outside min/max or matched by disabledDates, they stay in the grid and cannot be picked.

gog-icon

Icon

A thin wrapper around the library's built-in SVG set — and, since , around your own as well: register any SVG under a name and it works everywhere a built-in one does. Small on its own, but every other component that needs an icon (button, checkbox, dialog, input field…) renders through it.

The built-in set

Every GogBuiltinIconName, read off ICON_DEFS rather than typed in, so the list cannot fall behind the package. All of them are Lucide glyphs (ISC licence, notice shipped in the package) on one 24×24 grid, drawn with currentColor and inlined — no icon font and no runtime dependency. The set is outline-only apart from two pairs, checkbox / checkbox-checked and star / star-filled, which exist for a toggle that has to show both states; anything else is registered by the app.

Size and stroke from the context

--gog-icon-size is 1.2em, so an icon follows the font size of whatever it sits in — an icon in a heading is a heading-sized icon without anyone passing a size. The stroke width is --gog-icon-stroke-width, in the glyph's own units, so it stays proportional as the icon scales and a thin set is one token away.

An explicit size

There is no size input. Set --gog-icon-size on the instance — or on a subtree, or in a theme — when the icon should not follow the text.

Colour

There is no color input either: the glyph strokes with currentColor, so it takes the colour of the text around it — a status colour, a link, a muted label.

Decorative or named

Icons are aria-hidden by default, since they almost always repeat the text beside them. For a standalone icon that carries meaning on its own, set [ariaHidden]="false" and a title: it becomes role="img" named by it . As the only content of a button, leave the icon decorative and name the button with ariaLabel.

A one-off template

template replaces the SVG entirely and wins over name outright. It costs an <ng-template> at every use site, so it is for the single glyph that has no business in a shared set; anything used twice belongs in provideGogIcons.

An unknown name

The icon asks for rokcet. It renders an empty host and, in dev mode, logs one console warning per name — not one per instance, so a typo inside an @for of a thousand rows is one line. It never throws: an icon is decoration, and taking a page down over a misspelt glyph would be the worse failure.

Used by name, everywhere

A registered name works anywhere an icon name is taken — gog-icon itself, wherever it is placed, and the iconName inputs of components such as the tag and the chip — with no <ng-template> at the use site. That is why a registry beats the template input for an icon set.

A registration wins over a built-in, and a nested one layers on

The second group sits under a directive that calls provideGogIcons again with one icon named copy. Inside it, copy is the registered glyph — that is how an app swaps the library's checkmark or chevrons everywhere at once, with no call site touched — while cart, registered above it, is still there: a nested registration adds to its parent's set rather than replacing it, the same as provideGogConfig.

Write the SVG for inheritance — and only markup you wrote

  • Give it a viewBox and stroke="currentColor" (or fill), and no width or height — gog-icon drives size and stroke width from the --gog-icon-* tokens, so a registered icon scales and colours exactly like a built-in.
  • Security. Registered markup is inserted with bypassSecurityTrustHtml, because Angular's HTML sanitizer strips SVG. That is safe for static markup you authored or imported at build time, and unsafe for anything derived from user input or fetched at runtime. For remote icons, fetch them yourself, run them through a real SVG sanitizer, and register the result.

Accessibility

Decorative by default: an icon usually repeats the text beside it, and announcing both says everything twice.

  • Default — aria-hidden="true" on the host. Beside text, there is nothing to do.
  • Named — [ariaHidden]="false" makes it role="img", named by title or else by the icon's name. A name like more-vertical is rarely what a person should hear, so set the title. Written as a plain attribute, title also lands on the host as the HTML title, so the browser shows it as a tooltip on hover.
  • In a button — when the icon is a button's only content, keep it decorative and name the button (ariaLabel on gog-button): the name then belongs to the thing that is pressed, and a screen reader says it once.
  • Keyboard — none. An icon is never focusable.

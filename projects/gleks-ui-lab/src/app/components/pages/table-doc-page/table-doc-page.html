gog-table

Table

A sortable, paginated data table with custom cell/header templates, size variants, sticky headers, loading and empty states, and built-in row numbers. Since it also reports what the user did (gogSortChange, gogPageChange, gogRowClick), hands sorting and paging to a server (lazy), and selects rows — so it is no longer a display-only grid.

Overview

Import TableComponent and GogColumn from @guildofgleks/ui/table, then declare one <gog-column> per field as content — the columns live in your template, not a config array. The entry point carries the column template directives and the table's event types too, and lets a table used only behind a lazy route keep its own code out of the initial bundle; what it imports from the root package (paginator, select, checkbox, scroll, spinner) loads wherever the root package already does.

Basic usage — sortable columns cycle asc → desc → unsorted on click. A sortable header holds a real <button> , so it is one tab stop that Enter and Space sort, and the order is stated by aria-sort on the header cell.

Examples

Sizes

size is row density, from xsm through slg; the default is lg. Hover on a sortable header is live.

Loading and empty

loading replaces the body with a spinner and marks the host aria-busy. An empty value renders one row saying "No data" ; emptyMessage sets it per table, because "No orders yet" and "Nothing matches these filters" are different sentences, and GOG_CONFIG.labels.tableEmpty sets it app-wide.

An empty state of your own — gogTableEmpty

An <ng-template gogTableEmpty> inside the table replaces emptyMessage when there are no rows. Put a gog-empty-state in it and a table emptied by a filter is announced: the plain message is text in a cell, which changes on screen without a word to a screen reader. Clear the search, then type something that matches nothing.

Custom cell and header markup

A column swaps its default text for a gogColumnBody or gogColumnHeader template declared inside that column. The body context carries the row, its index and the resolved cell value. [gogColumnBodyTypeOf]="rows" types let-row against the same array, so a typo in row.status fails the build under strictTemplates; it is never read at runtime. In a sortable column a header template renders inside the sort button and becomes its name — keep it to text and decorative marks.

Columns and missing values

showRowNumbers is on by default; showColumnBorders draws the vertical rules. A null or undefined cell renders emptyPlaceholder — "-" unless set; "Accordion" has no owner. width, minWidth and maxWidth size a column.

Full width

Full width of its container by default. [fullWidth]="false" sizes the table to its columns, measured against their content — for a narrow two-column table that should not stretch across a wide page.

Pagination and total

pageSize above 0 pages the rows with the same gog-paginator documented separately. showTotal adds a row count; totalPosition places it (opposite the paginator by default) and paginatorPosition places the pages.

Sticky header

stickyHeader puts position: sticky on the header cells, and maxHeight gives them something to stick to: it caps the table's own scroll viewport. The two go together — without the cap the viewport is as tall as its content and the header rides away with it. It has to be the table's own viewport: the table wraps its markup in a horizontal gog-scroll, and a scroller moving on one axis is a scroll container on both, so nothing outside the table can be the header's scrollport. Scroll this one down and sideways. The frame stays put while rows scroll, and the vertical scrollbar starts below the header .

App-wide labels — GOG_CONFIG

The total's word, the empty message and the names of the pagination and the selection checkboxes come from GOG_CONFIG.labels; the rows-per-page select from GOG_CONFIG.paginator. In an app the provider goes in app.config.ts — see Global Configuration.

Reacting to the user

The table had no outputs at all before 21.4.0, which is what made it display-only. It now reports the three things a consumer needs to know about: a new sort, a new page, and a click on a row.

Sort a column, page through, click a row — newest event first:

gogPageChange is deliberately quiet twice. It does not fire on the first render, and it does not fire for the reset to page 1 that a new sort causes — that reset belongs to the sort. Without both rules a consumer refetching from each event would issue two requests for one user action.

gogRowClick alone is a mouse-only affordance: a <tr> is not focusable. interactiveRows makes rows focusable and styles them as clickable, so Enter and Space activate the focused one. If the action really is "open this one thing", a link or button inside a cell beats a whole-row target.

Selection

selectionMode turns it on; [(selection)] is always a T[], including in 'single' mode where it holds zero or one row. One shape to read beats a T | T[] | null union to narrow on every access.

Two rules worth stating outright, because both are silent when you get them wrong:

  • Set dataKey. Without it rows are matched by object identity, so any refetch that produces new objects drops the selection with nothing to show for it. It is also the @for track key, which is what lets the rendered DOM survive a refetch instead of being rebuilt.
  • Select-all covers the current page, not the whole data set. In lazy mode the table has never seen the other pages, and a control that meant different things in the two modes would be worse than either behaviour on its own.

The checkbox column appears on its own, and showSelectionColumn turns it off. The header select-all renders only in 'multiple' mode.

Selecting by row — selectOnRowClick

[selectOnRowClick]="true" toggles a row's selection when the row itself is pressed, so the checkbox column can go. Click a row to select it and again to deselect it; the Open button stands in for an action in a cell.

  • It makes the rows interactive on its own — focusable, styled as pressable, and toggled by Enter or Space on the focused row — so there is no interactiveRows to pair it with.
  • Two presses do not toggle. One that lands on a control inside a cell — a link, a button, a form field, the row's own checkbox — keeps its own meaning, which is why Open above does not select its row. And a drag that selects text in the row selects the text, so a value can still be copied.
  • gogRowClick still fires for every press. A table whose rows navigate — open a detail page — should leave selectOnRowClick off, or one press would select and navigate at once.

With the checkboxes off, the selection still reaches a screen reader. A selected row's first cell starts with visually hidden text, "Selected", set app-wide through GOG_CONFIG.labels.tableRowSelected. aria-selected on the row is not enough on its own: ARIA supports it on a row only inside a grid, and a plain table is not one. With the checkbox column shown, the checkbox states it and nothing is added.

Rows per page

pageSize is a model, not a plain input: [pageSize]="20" works exactly as before, and [(pageSize)]="size" became possible. That is the whole reason the rows-per-page select needs no wiring — the table binds its own model straight to the paginator's, and the select writes back through it with no intermediate signal to keep in sync in either direction.

The select is off by default, per table or app-wide through GOG_CONFIG.paginator — see Global Configuration. Changing the size returns to page 1 and does not emit gogPageChange: you already know from pageSizeChange, and firing both would make a lazy table fetch twice. The footer stays visible at a single page whenever the select is on, so the user is never stranded on a size with no control left to change it.

Server-driven tables — lazy

By default the table owns the whole data set: it sorts value and slices the page itself. With [lazy]="true" it does neither — value is the current page, already sorted, rendered exactly as handed over. Give it totalRecords so it knows how many pages exist (without it, pagination stays hidden and it warns in dev mode), then refetch from the outputs.

137 rows that only ever leave the "server" one page at a time, with a 350 ms delay so the loading state is visible. Sorting and slicing happen in the fake endpoint — which is the point: the table must not re-order or re-slice what it is given.

Row numbers still count from the current page ((page - 1) * pageSize + i + 1), and showTotal reports totalRecords rather than value.length. Do not sort or slice value yourself as well — that is exactly what the flag turns off.

Set sort when the server already orders the data. This endpoint answers by score, highest first, until told otherwise; [sort]="serverSort()" makes the Score header say so on the first render, where an unbound table would show every header unsorted. Setting sort does not fire gogSortChange, so binding the two — [sort]="sort()" (gogSortChange)="sort.set($event)" — is a two-way binding, not a loop.

In lazy mode pageSizeChange is the refetch signal for a new page size, so bind [pageSize] + (pageSizeChange) rather than the banana-box when you need to act on it.

Virtualized rows — virtualize

[virtualize]="true" renders only the rows in view. The table below holds 10 000, and every seventh carries a note long enough to wrap — so the rows genuinely differ in height, which is the case a table has and a dropdown does not. A row's height cannot be pinned: height on a <tr> or <td> is a minimum in table layout. So the window measures each row as it renders, and the scroll height sharpens as you scroll rather than being exact from the first frame.

It requires maxHeight and fullWidth, and both are measured constraints rather than preferences. Without maxHeight the table never scrolls on its own, so there is no viewport to window against; [fullWidth]="false" lays out with table-layout: auto, which sizes columns from whichever rows happen to be rendered. Switch either off and windowing turns itself off, with a warning in dev mode.

aria-rowcount and aria-rowindex keep the announced size and position honest, and gogRowClick's index still counts from the top. It is off by default and never switches itself on at a row count, because a windowed table behaves differently in ways a page can notice — the browser's find only sees rendered rows, and a :last-child selector matches the last rendered one.

lazy is not a substitute, and the two compose. The lazy flag keeps the fetch small and still stamps every row of the page it was handed; virtualize keeps the rows the browser builds small, whatever was fetched. One ceiling worth knowing: Chrome clamps an element's height at 33 554 426px, roughly 745 000 rows.

The window starts on the server. A server-rendered page carries a screenful of rows rather than all 10 000, and hydration takes over from there. maxHeight takes any CSS length for this: rem, vh or calc() window from the first frame as px does.

Where it stops

Stated here so you find out now rather than halfway into a project. gog-table has no column resizing or reordering by the reader — a column's width, minWidth and maxWidth are yours to set, not theirs to drag — no frozen columns, no expandable rows and no row grouping.

stickyHeader is not the missing feature in disguise: it pins the header while rows scroll under it, which is the vertical axis. Freezing a column against horizontal scroll is the other axis, and that one is absent. For a full data grid, use a dedicated one.

Accessibility

A native table: headers are <th scope="col">, sorting is aria-sort on the header, and each selection checkbox is named.

  • Name — ariaLabel names the table ("Orders") and, whenever its columns overflow, the scrolling region around it. An overflowing table is a Tab stop, so it needs a name to be told apart from the page; without one it warns in dev mode, once per page.
  • Sorting — a sortable header holds a real <button>, named by the header text; aria-sort on the cell states the order.
  • Rows — a <tr> is not focusable, so gogRowClick alone is mouse-only. interactiveRows (or selectOnRowClick) makes rows focusable, and Enter or Space activates the focused one.
  • Selection — the checkboxes are named by GOG_CONFIG.labels.selectRow / selectAllRows; with the column off, a selected row's first cell starts with visually hidden "Selected" (labels.tableRowSelected).
  • State — aria-busy while loading; an empty table says so in a row of its own, which a screen reader is not told about — a gogTableEmpty holding a gog-empty-state is. A virtualized table keeps aria-rowcount and aria-rowindex honest about the rows it is not rendering.

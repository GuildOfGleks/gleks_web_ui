gogTooltip

Tooltip

A hover/focus tooltip as a directive, not a component — drop it on any element, a gog-* component's own host tag or a plain native one, and that element needs to know nothing about it.

Overview

Examples

Position

auto (the default) picks whichever side has room, preferring top, then bottom, then right, then left. An explicit side still flips to its opposite when it has no room but the opposite does, so a tooltip near the viewport edge stays readable rather than clipped. The bubble also caps its width against the viewport.

Text and templates

gogTooltip takes a string, or a TemplateRef for richer content. A long string wraps at --gog-tooltip-max-width; past --gog-tooltip-max-height the bubble scrolls inside an internal gog-scroll. Keep it a hint: a tooltip cannot hold a control, since nothing in it can be reached by keyboard.

Delays

gogTooltipShowDelay defaults to 300 ms, which keeps tooltips from flashing as the pointer crosses a toolbar; gogTooltipHideDelay defaults to 100 ms, which is what lets the pointer travel from the trigger onto the bubble.

Hoverable, dismissible, and disabled

Move the pointer from the trigger onto the bubble: it stays, so a long one can be read (WCAG 2.1 SC 1.4.13). Press Escape while it shows: it goes, and the trigger keeps focus. gogTooltipDisabled turns one off without removing the directive.

App-wide defaults — GOG_CONFIG

Position and both delays fall back to GOG_CONFIG.tooltip before their defaults, so a house style is set once; an instance's own input still wins. In an app the provider goes in app.config.ts — see Global Configuration.

Restyling one bubble

The bubble is appended to document.body, so it is never clipped by an ancestor's overflow: hidden — and so a --gog-tooltip-* token set on an ancestor of the trigger never reaches it. gogTooltipClass puts a class on the bubble itself, and the rules for that class have to come from a global stylesheet:

Visually the bubble is the same floating-panel recipe as a dialog panel or a dropdown — surface background, plain border, panel shadow — rather than a bespoke inverted bubble, so it reads as part of a themed app.

Accessibility

Shown on both hover and keyboard focus, dismissible with Escape, and hoverable so a long bubble can actually be read.

  • Description — while the bubble shows, the trigger points aria-describedby at it, so the hint is read after the trigger's own name. Hidden, it is not in the tree at all. The attribute goes on the element that takes focus — on a gog-button, the inner <button> — and the tooltip adds its id to whatever is already there and removes only its own, so a field's error message stays linked.
  • Keyboard — focusing the trigger shows the bubble, Escape dismisses it. Focus is tracked with focusin / focusout, which keeps it replay-safe under SSR event replay.
  • Only on something focusable — a tooltip on an element that cannot take focus is out of reach for a keyboard user. The icon in the overview is reachable by hover only; on a real page, put the hint on a control.
  • Inside a dialog the tooltip stacks above it — the dialog panel raises --gog-tooltip-z the same way it raises the dropdown's.

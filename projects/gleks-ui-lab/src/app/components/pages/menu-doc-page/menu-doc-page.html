gog-menu

Menu

A command menu opened from a button you own. [gogMenuTrigger] goes on your button, gogMenuItem on your items — so an item can carry an icon, a label and a shortcut hint without an input per piece. A closed menu renders nothing at all, so its commands are not in the accessibility tree until it opens.

Overview

Import the component and the two directives. The trigger is a directive rather than a component of its own — the same decision as [gogButton] — because a menu button is usually an icon button you have already styled, and a wrapper would fight that. It goes on a gog-button as well as on your own <button gogButton>: since it writes aria-haspopup, aria-expanded and aria-controls onto the inner <button> that takes focus, and Escape hands focus back to it.

An item is your own <button gogMenuItem>, so its content is yours — an icon, a label, a shortcut hint. The hint's styling below is inline because the library draws none for it: it is your markup, styled however your app styles a <kbd>.

There is no appendToBody. The panel always renders into <body> and is placed from the trigger's measured rect, so a menu inside gog-scroll, gog-table or any overflow: hidden ancestor is not clipped and needs nothing configured. It also takes the --gog-dropdown-z its trigger inherits, so a menu opened inside a gog-dialog stacks above the dialog rather than behind it.

Examples

Row actions

What the component was built for: an icon button per row. The library created this gap itself — 21.4.0 added the more-horizontal / more-vertical icons and a table built for row actions, with nothing to open with them. The table wraps itself in a gog-scroll and the panel still escapes it, which is why the menu always renders into <body> rather than offering a mode to get this wrong in.

Disabled items

An item is your own <button>, so you disable it the way you disable a button: the native disabled attribute, static or bound — there is no input for it. A disabled item stays in the list rather than disappearing, since removing it would shift every other item under the pointer; the arrow keys step over it, and clicking it does nothing. With Locked on, the second menu leaves only Open reachable, and ↓ from it wraps back to itself instead of landing on a dead command.

A long menu scrolls itself

The panel's height is the smallest of three: its own content, --gog-menu-max-height (320px by default), and the room between the trigger and the viewport edge. Past that it scrolls with gog-scroll — the same thin, auto-hiding scroller as everywhere else in the package, with overscrollBehavior="contain" so a wheel at the end of the list does not scroll the page behind it. Arrowing past the last visible item scrolls it into view.

Lower the token to make a menu start scrolling sooner — that is the knob, and it is the one thing about this component that did not work in 21.5.0, fixed in 21.5.1: the measured room was written onto the panel as an inline max-height, which beat the rule the token feeds.

Direction

direction is auto by default: the panel drops down whenever it fits and flips up only when it cannot. Force it with up or down.

One menu, many triggers

A menu declared once can be opened from several buttons — row actions in a list. It opens beside whichever trigger opened it, and only that trigger reads as expanded (isOpenFrom(trigger) says which). The example records the file on the trigger's focus, which happens before the menu opens however it is opened.

Accessibility

The trigger says it opens a menu (aria-haspopup="menu"), whether it is open (aria-expanded) and which menu (aria-controls, while open) — on the inner <button> when the trigger is a gog-button. The panel is role="menu" of role="menuitem" buttons, with one tab stop: the trigger. A closed menu is not in the DOM at all, so nothing of it reaches the accessibility tree. The panel is named by ariaLabel, which is empty by default — name every menu.

The keyboard is the WAI-ARIA menu button pattern, in full. This is most of what the component is for — none of it is visible in a screenshot, and it is the part a hand-rolled dropdown almost always leaves out. Open the overview menu and try it.

@for (row of keyboard; track row.keys) { }
Key What it does
{{ row.keys }} {{ row.action }}

A press outside closes the menu without pulling focus back — the click landed somewhere the reader chose, and stealing focus from it would undo their own action.

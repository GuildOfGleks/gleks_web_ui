gog-paginator

Paginator

Page-number controls with no notion of rows or columns, so they drop into a table, an accordion, a plain list, or anything else you page through. Hand it a row count and it works out the pages itself; hand it a page count and it uses that.

Overview

Import the component and drop it into a template.

page is a two-way model — [(page)]="mySignal" — and totalPages is the only other thing the paginator needs. By default it shows a fixed, centred window of page buttons that slides as you navigate.

Examples

Sizes

Five steps, from xsm through slg. The current page is the one primary button; the rest are ghost buttons.

States

On the first page "previous" is disabled, on the last "next". disabled freezes every control — useful while the page it navigates is itself loading. Hover, focus and press are the buttons' own and are live.

Range modes

window (the default) keeps visiblePages buttons and slides them to centre the current page, clamped at the edges; showFirstPage and showLastPage pin the ends with a "…" between. ellipsis always pins the first and last page and keeps siblingCount pages either side of the current one — the look gog-table uses.

Paging a row count — totalRecords

Usually you know how many rows there are, not how many pages. With totalRecords the paginator derives the page count from pageSize itself, so nothing is recomputed when the rows-per-page select changes it — and changing it returns to page 1, the only position that means the same thing at every size. totalPages is still right when a server reports a page count; totalRecords wins when both are set. The select is off by default. pageSize is a model here and on the table, which is what lets the two bind straight to each other.

A page count that shrinks under the current page

The paginator is on page 8 of 8. Drop the total to 3 and it writes page 3 back through page rather than showing a page that does not exist.

Full width

On by default: the paginator takes its container's width — the dashed box here. [fullWidth]="false" shrinks it to its buttons.

App-wide defaults — GOG_CONFIG

The navigation's name and the button labels come from GOG_CONFIG.labels — pagination, previousPage, nextPage, rowsPerPage, and page, a function (page, isCurrent) => string that names each number button. Whether the rows-per-page select shows, and its choices, come from GOG_CONFIG.paginator. In an app the provider goes in app.config.ts — see Global Configuration.

Accessibility

A navigation landmark of real buttons, each named for where it goes.

  • Landmark — a <nav> named by ariaLabel, or GOG_CONFIG.labels.pagination.
  • Names — the page numbers are "Go to page N"; the current one is "Page N" with aria-current="page" carrying its state. A screen reader announces that itself, so a translated labels.page should leave the "current" half out. The step buttons are named from config, since ‹ and › say nothing on their own.
  • Keyboard — Tab moves through the buttons and the rows-per-page select; Enter or Space presses. A disabled step button is a native disabled button, out of the tab order.

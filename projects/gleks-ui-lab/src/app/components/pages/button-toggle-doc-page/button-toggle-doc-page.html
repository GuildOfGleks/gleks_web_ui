gog-button-toggle-group

Button Toggle

A row of buttons where one — or, with multiple, several — can be picked. Options-driven, taking your own objects through the same optionLabel / optionValue / optionDisabled accessors Select uses.

Appearance and orientation

joined is one segmented control sharing borders; separated is discrete buttons with a gap. Either works vertically.

Sizes

Five steps, in both appearances — also settable app-wide through GOG_CONFIG.control.size (see the last example).

States

Nothing selected, one selected, a single option disabled through optionDisabled, and the whole group disabled — then the multiple mode with none and all of its options on. A disabled option stays in place and is skipped by the arrow keys rather than merely being unclickable.

Icons

optionIcon takes the same accessor shape as the other option inputs — a property path or a function — and draws a leading icon on each button.

Custom button markup

A gogButtonToggleOption template replaces the button's content, with {{ '$' }}implicit, selected, disabled and the resolved label in its context. Bind [gogButtonToggleOptionTypeOf] to the same array as options and the option is typed as its element — option.icon below is checked under strictTemplates. The binding is never read at runtime; left unbound, the option is unknown, as before.

The icon-only group keeps each button's name: label goes into the button as text hidden with the library's gog-visually-hidden class, so a screen reader still hears "Search", "Filter", "Star".

Full width

fullWidth stretches the group to its container — the dashed box here — and the buttons share the width.

Two-way binding and forms

value is a model, so [(value)] works in both modes and valueChange fires on every pick. The group is also a ControlValueAccessor: a formControl drives it, and disabling the control disables the group.

App-wide defaults — GOG_CONFIG

control.size sets the default size and ripple.enabled the press ripple for every group under the provider; an instance's own input still wins. This example provides the config on itself so it reaches only its own groups — in an app it goes in app.config.ts. See Global Configuration for every key.

Single and multiple are different widgets

multiple is not a cosmetic switch. In single mode the group is a radio group — role="radiogroup" / role="radio" with aria-checked, and the arrow keys move and select, because that is what a radio group does. In multiple mode it is a toolbar of independent toggles — role="group" with aria-pressed, arrows only move, and Space or Enter toggles. Getting this backwards is the usual defect in this component; here it follows from the input. With multiple, value is an array.

Accessibility

The roles follow multiple, as described above. The group is one tab stop: Tab lands on the selected option, or on the first enabled one when nothing is selected.

  • Single mode — the arrow keys move to the next enabled option and select it.
  • Multiple mode — the arrow keys move focus only; Space or Enter toggles the focused option.
  • Disabled — a disabled option is skipped by the arrows; a disabled group is out of the tab order.
  • Name — set ariaLabel on the group: the buttons alone ("List", "Grid") rarely say what is being chosen. An icon-only button needs its label kept as hidden text, as in Custom button markup.

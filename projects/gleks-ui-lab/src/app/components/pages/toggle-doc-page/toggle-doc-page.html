gog-toggle

Toggle

An on/off switch: a native <input type="checkbox"> carrying role="switch", so it announces as "switch, on" rather than "checkbox, checked" while the platform keeps owning the keyboard and forms.

Examples

Sizes and states

Off, on, and both disabled, in the five sizes — a switch has no third state, which is the first thing that separates it from a checkbox. The track and thumb have their own scale (--gog-toggle-<size>-*); only the label size is shared with gog-checkbox. Both states stay legible while disabled.

Labels inside the track

onLabel / offLabel render inside the track — the one thing a checkbox cannot do. Both stay in the DOM and the track sizes to the wider of the two, so its width cannot jump as the switch flips; the inactive one is faded, not removed. Keep them short, and do not put the state's meaning only there: they are aria-hidden, because the role already announces on and off.

Label position

The control is a <label> around the input, so its text is the accessible name and the whole row is the hit target. labelPosition="start" puts the text first — what a settings list wants, so the switches line up on one edge.

A settings list — full width

fullWidth fills the container — the dashed box here. With labelPosition="start" that is the row every settings screen is made of: label at one edge, switch at the other, the whole line pressable.

No visible label

ariaLabel names a switch when the row around it already says what it is — a table cell, a toolbar. It is the only case that input is for.

Two-way binding

A switch takes effect immediately — there is no Save button between the press and the setting, which is the behavioural half of the difference from a checkbox. That makes checkedChange the place to do the work.

Reactive forms

A ControlValueAccessor, so formControl / formControlName work directly: the form drives checked, and disabling through the form ends up as disabled on the native input.

App-wide defaults — GOG_CONFIG

control.size sets the default size for every toggle under the provider; an instance's own input still wins. This example provides the config on itself so it reaches only its own toggles — in an app it goes in app.config.ts. See Global Configuration.

Toggle or checkbox?

A switch answers "is this setting on" and applies at once; a checkbox answers "is this one of the things you selected" and waits for the form around it. That is why this component has no indeterminate, no error line and no group: a list of switches is a list of independent settings, while a list of checkboxes is usually one answer made of several parts. Reach for Checkbox inside a form and for gog-toggle in a settings list.

Accessibility

The control is a real checkbox input with role="switch" — the only ARIA on it. The state is the input's own checked property, so there is no aria-checked, and Space, form submission and a :checked selector all keep working.

  • Keyboard — Tab reaches it, Space flips it.
  • Name — the label, or ariaLabel when there is no visible one.
  • Painting — the track, the thumb and the two track labels are aria-hidden; painting it differently is the entire difference from gog-checkbox.

gog-slider

Slider

A native <input type="range"> under a drawn track: one value or a two-thumb range, horizontal or vertical, with a label, a steady readout and full ControlValueAccessor support.

Examples

States

Five states, each in both modes. A slider has no size input: its track, thumb and type come from the --gog-slider-* tokens alone. [showThumb]="false" draws a meter-like bar that still answers the pointer and the keyboard — there is just nothing drawn to grab. Disabled dims the whole control once, label and error included.

min, max and step

step works at any scale. The readout reserves the width of the longest number min, max and step can print and uses tabular figures, so it never shifts as the value changes. It is a plain number — there is no formatter, so a unit or a currency belongs in the label.

Vertical

The same native input turned with writing-mode, not a custom drag, so dragging, touch and every arrow key keep working; the value grows upward, like a fader. Its length is --gog-slider-vertical-length (160px), and fullWidth does nothing here — a vertical slider's width is its thickness.

Width

Full width by default — the opposite of the other controls, because a track has no content to size to. [fullWidth]="false" takes --gog-slider-auto-width (240px) instead of shrinking.

No visible label

ariaLabel names a slider that has no label. On a range slider it names both thumbs, followed by "Minimum" and "Maximum" — before, those thumbs were a bare "Minimum" and "Maximum".

Range — two thumbs

range puts a second thumb on the track and switches the model: bind [(rangeValue)], a GogSliderRange { start, end }, instead of [(value)]. Each thumb is its own native input and its own Tab stop, and neither can pass the other — a drag that tries stops where the other thumb is. Only the thumbs take the pointer in this mode: a press on the bare track does nothing, the price of two inputs sharing one track.

Thumbs that meet

Both thumbs start at 200, on top of each other at the end of the track. Drag left: the start thumb comes away . Before, the end thumb was always the one under the pointer — it can go neither past max nor below the start thumb, so a mouse or a finger had no way out; only the keyboard did. The form control here carries the { start, end } pair: in range mode, that is what it holds.

Pinning one end

startDisabled / endDisabled pin one end and leave the other movable. They add to disabled rather than replace it, and unlike it they dim only the pinned thumb — the track stays live for the other.

A value outside min and max

The control draws a value clamped to [min, max] but does not write the clamp back: bound to 150 with max at 100, it shows 100 and the model still reads 150 until someone moves the thumb. Clamp at the source if the model has to agree. A form control's writeValue is different — it does clamp.

Reactive forms

Validators.min(20) on a control that starts at 10. With errorDisplay="auto" the error waits until the slider is touched — focus it and Tab away, or use the button — and moving the thumb past 20 clears it.

App-wide defaults — GOG_CONFIG

control.errorDisplay is the only key a slider reads. Both sliders start at 10 under Validators.min(20): the first takes 'auto' from the config and holds the message back until it is touched; the second sets 'manual' itself and shows it at once. orientation has no config key — it is a layout decision, not a house style. See Global Configuration.

Accessibility

A native <input type="range"> under a drawn track: the slider role, the value and the keys all come from the platform, and the drawing is out of the accessibility tree.

  • Keyboard — the arrow keys move one step, Home/End jump to min/max, and Page Up/Page Down take larger steps. Vertical answers Up/Down as well as Left/Right. In range mode each thumb is its own tab stop.
  • Name — a visible label names the input through for; without one, ariaLabel. With neither the input is still named "Slider", which says nothing — do not ship that. One <label> cannot name two inputs, so each range thumb carries its own aria-label: the label (or ariaLabel) followed by "Minimum"/"Maximum", or by startAriaLabel/endAriaLabel.
  • Value — explicit aria-valuemin/max/now follow the value as it moves. On a range thumb the bounds narrow to the other thumb, since that is as far as it can go.
  • Error — aria-invalid and an aria-describedby pointing at the message.
  • Pointer targets — in single mode the whole track is the target. In range mode only the thumbs are, and each takes the pointer across 24x24 (--gog-slider-range-target-size, WCAG 2.5.8) centred on the drawn thumb, horizontal or vertical . The keyboard reaches both thumbs fully either way.

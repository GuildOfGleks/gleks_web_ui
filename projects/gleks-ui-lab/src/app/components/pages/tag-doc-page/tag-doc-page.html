gog-tag

Tag

An informational status label with four semantic variants, two shapes, five sizes, and width that follows the text without wrapping by default.

Variants and sizes

Four status colours at each of five sizes. Every surface — the fill, the border, the text — is mixed from one colour per variant, so the four read as one family in every theme. The colour is a hint, never the message: the text has to say "Paid" or "Overdue" on its own, for anyone who cannot tell green from red. A tag has no interactive states.

Shapes and icons

rounded (the default) or pill, without an icon, with iconName — any built-in or registered name — and with a gogTagIcon template, which replaces the icon with any markup and wins when both are set. The icon is sized from the tag's own scale, not from --gog-icon-size.

Width

A tag fits its text and never wraps: two words of a status splitting across lines reads as two tags. fullWidth stretches it across its container — the dashed box — text centred. Text longer than its room ends in an ellipsis inside the border . A screen reader still reads it in full, but a sighted reader loses it, so keep a status short or show the whole of it somewhere else.

A colour outside the four — --gog-tag-accent

The four variants cover status. For a category — a team, a label colour a user picked — set --gog-tag-accent on the tag and the fill, border and text are all derived from it the same way. Check the contrast of a colour you bring: the library's own four are measured in every theme, and yours is not.

Accessibility

A tag is text in a coloured box. It has no role and no name of its own, and its icon is decorative.

  • Host — no ARIA at all, so a screen reader reads the tag's text where it stands, as it would any span.
  • Icon — aria-hidden whichever way it was given, so an icon cannot be the only thing that says what a tag means.
  • Changes — a tag that must interrupt, like a status that changes while the page is open, needs a live region around it; gog-alert is the component for a message that has to be heard.
  • Keyboard — none. A tag is not focusable.
  • Tag, chip or badge — a tag labels something and does nothing when pressed. A chip is something to press, toggle or remove. A badge is a count pinned to the corner of another control. If a tag starts needing a click handler, it has become a chip.

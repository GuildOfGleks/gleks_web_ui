dir="rtl"

Right-to-left

Set dir="rtl" on <html> — or on any wrapper — and every component mirrors. There is nothing to configure per component, no separate stylesheet to import and no RTL build of the package.

Use it

That is the whole API. The demo below puts dir on a region rather than on the document so you can flip it and compare — watch the field label and its icon change ends, the checkbox move to the other side of its text, and the slider and progress bar fill from the opposite edge. Open the select: its panel renders into <body> and still mirrors with the region, not with the page around it.

Known defect in {{ libraryVersion }}: a gog-inputfield icon overlaps its own text in RTL. The icon itself mirrors correctly — it is placed with inset-inline-start — but the space reserved for it in the input is still a physical padding-left, driven by --gog-input-pl. So in RTL the icon sits at the right edge while the 36px reserve stays at the left, and the text starts underneath the icon. The Search field above shows it; flip to dir="ltr" to see the same field render correctly. It affects iconStart, iconEnd and the trailing controls that share that slot (clearable, the password toggle). The fix is the same rule in logical form; nothing about the API changes.

In your own styles

Write logical properties (margin-inline-start, inset-inline-end, text-align: start) and your own CSS mirrors along with the library's. For the handful of properties that have no logical form — transform-origin and translate — the library declares three custom properties that flip on [dir='rtl'], and they are yours to use:

@for (row of directionProperties; track row.name) { }
Property LTR RTL What it is for
{{ row.name }} {{ row.ltr }} {{ row.rtl }} {{ row.description }}

They are ordinary custom properties on the same cascade as everything else on the Theming page — a nested dir re-declares them for its own subtree, the way a nested data-theme re-declares a palette.

gog-chip

Chip

A compact, clickable label with five sizes, two shapes, and optional avatar, icon, and remove affordances.

Sizes and states

Six states at each of the five sizes, all live — hover and press are the chip's own and cannot be forced from a page. selected is tri-state: unset, the chip is a plain chip; false and true make it a toggle that is off or on, and on draws an inset ring rather than a fill, because hover and press already own the background. A disabled chip keeps its ring — "on, and unavailable right now" is a real state. [clickable]="false" is a label: no hover, no press, not a button.

Avatar, icon and remove button

The avatar, the icon and the remove button are each a ratio of the chip's own font size, so the whole object scales from one number. avatarUrl and iconName are independent — set both and both render.

Shapes

rounded (the default) or a fully rounded pill, with and without an avatar and a remove button.

Filter chips

[(selected)] turns a row of chips into toggles that need no click handler: each flips its own value on click, Enter and Space, and announces aria-pressed. gogClick still fires, after the flip, so a handler reading the value sees the new one; if the page drives the state itself from that handler, bind one-way — [selected] — or the two flips cancel out. For a choice of exactly one, this is the wrong component: use gog-button-toggle-group or a radio group.

Removable

removable adds a button that emits gogRemove; the chip does not remove itself, the list it came from does. The button works from the keyboard : Tab to it and press Enter or Space. Give each a removeAriaLabel that says what it removes — the default, "Remove chip", is the same for every chip in the row. These chips are [clickable]="false", since removing is their only action. A disabled chip hides its button rather than offering one that does nothing.

Full width

Off by default. On, the chip fills its container — the dashed box here — and the remove button stays at the end.

App-wide defaults — GOG_CONFIG

The ripple is the only key a chip reads: ripple.enabled turns it on for every chip under the provider, and an instance's [ripple] still wins. Press each. A chip that is not clickable never ripples — a label that waves at a press promises something it will not do. In an app the provider goes in app.config.ts — see Global Configuration.

Accessibility

A clickable chip is a role="button" with a tab stop; a filter chip adds aria-pressed; a label chip is plain text.

  • Name — the chip's content, or ariaLabel. A removable chip is two sibling buttons, so the chip is named by its content alone — "Angular", not "Angular Remove filter Angular" — and the remove button by removeAriaLabel.
  • Keyboard — Tab reaches the chip and then its remove button; Enter or Space presses whichever has focus.
  • State — aria-pressed while selected is true or false. false is written, not left out, because a chip with no aria-pressed is not a toggle to a screen reader at all; null writes nothing. A disabled chip drops role="button" and with it aria-pressed, though it keeps the ring on screen.
  • clickable is on by default, so every chip is a button and a tab stop unless it says otherwise. A chip that only shows a value should set [clickable]="false", or a keyboard user tabs through buttons that do nothing. For a coloured status label, gog-tag is the component.

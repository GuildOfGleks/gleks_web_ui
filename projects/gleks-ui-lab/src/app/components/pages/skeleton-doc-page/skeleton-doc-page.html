gog-skeleton

Skeleton

A placeholder bone that mirrors the shape of content still loading — text lines, avatars, images, cards — so the layout holds still and the user never stares at a blank screen.

Examples

Shapes and sizes

text is a line at the height of that size's text, circle an avatar, rect a media block. text and rect fill their container's width, which is why every bone here sits in a cell of its own.

Animations

pulse (the default) fades the bones in and out, wave sweeps a highlight across them, none holds still — for a surrounding UI that is already busy. Under prefers-reduced-motion both animations stop, whatever the input says.

Lines

lines stacks bars with the theme's spacing between them, and past one line the last is shorter — the silhouette a real paragraph leaves.

Width, height and corners

width and height take any CSS length, to match the thing that will replace the bone. A circle given only a width stays a circle. height is ignored on text, whose line height comes from size. [rounded]="false" squares the corners for content that has square ones.

Composed — a card that loads

A screen loads a layout, not a shape: an avatar, a title, a paragraph, a picture. Built from bones the size of what replaces them, the card keeps its height while it loads — 284px loading against 289px loaded here, in the default theme — so what is below it barely moves when the content lands. The part that needs matching by hand is the paragraph: it wraps to three lines, so its bone has [lines]="3". A bone's line height comes from its size, not from your font — count the lines and measure. The card reloads for two seconds on demand.

Accessibility

Decorative by default: a loading page can carry dozens of bones, and each one speaking would be noise.

  • Default — a bone is aria-hidden.
  • One named bone — give ariaLabel to the one that stands for the whole loading area, and it becomes an indeterminate role="progressbar" with that name — the role a spinner takes, so a loading area reads "progress bar, Loading profile" whichever of the two draws it. That makes the area findable while reading; it does not announce anything when it appears. Before 21.19.0 it was role="status", a live region with no text to speak, so nothing that used to be said is lost.
  • The container — what tells a screen reader the area is changing is aria-busy on the container, as the composed card sets, and what tells it the content has arrived is the content.
  • Keyboard — none. A skeleton is not focusable.
  • Skeleton or spinner — a skeleton when the layout of what is coming is known, so the page does not jump when it lands; a spinner when it is not, or when the wait belongs to an action rather than to content.

gog-accordion

Accordion

An expandable content panel with single-open and multi-open modes, content projection for headers, chevrons and bodies, and a loading skeleton state.

Overview

Import the component and drop it into a template.

Basic usage — three sections, one disabled, the first expanded on load. The body comes from the gogAccordionContent template, which receives the item back, and gogToggle reports each press.

Examples

Sizes and item states

Every size, from xsm through slg; lg is the default. States belong to items, not to the accordion: each one here holds an open item, a closed one and one disabled through disabled: true on the item object. A disabled header cannot be opened and keyboard navigation skips it. Hover, focus and press are live — the page cannot force them. The three smallest sizes look closer together than lg and slg, and that is correct: they all label at --gog-text-xs, and the chevron is a ratio of the header's own type, so it does not manufacture a difference the type does not have.

Loading skeleton

While loading is on, each row is a placeholder: one per item when the items are known, skeletonCount of them when items is still empty. The chevron gets a placeholder too — or none, with showChevron off — so the row that arrives has the silhouette of the one that waited.

Single and multi-open

By default opening one item closes the one that was open. multi lets items open independently. openIds is two-way, so the page can read which are open.

Controlled open state

openIds is a model, so the app can also write it — the buttons set the whole set and the accordion follows.

Header and chevron templates

gogAccordionHeader and gogAccordionChevron both receive the item and its open state. A header template renders inside the header button, so it holds markup and never another control. It renders as written : the theme's title casing applies to the default title only, so the lines above are not uppercased in the themes that uppercase headers. The default chevron rotates by itself; a template draws its own open and closed look, and nothing rotates underneath it.

Heading level

headingLevel wraps each header in role="heading" at that aria-level, so screen-reader users can jump straight to a section. Leave it unset when the accordion isn't part of the page outline (e.g. nested in a card).

Accessibility

Each header is a real <button> that says whether it is expanded and which body it controls; each body is a region named by its header.

  • Role and name — the header button carries aria-expanded and aria-controls; the body is role="region" with aria-labelledby pointing at its header. With headingLevel set, each button sits inside role="heading" at that aria-level.
  • Keyboard — Tab moves between headers and into an open body; Enter or Space toggles the focused item; ArrowDown and ArrowUp move focus to the next and previous header, wrapping at the ends; Home and End go to the first and last. Disabled headers are skipped.
  • Closed bodies stay in the DOM, aria-hidden and inert, so nothing inside them takes focus or is read out.
  • Templates — a custom chevron is aria-hidden like the default one; aria-expanded on the header is what says open. A header template must not hold another control: a button inside a button is invalid and unreachable.
  • Loading sets aria-busy="true" on the host. The skeleton rows are aria-hidden, so the accordion reads as "coming" rather than empty.

Sizes and states

Off, on, indeterminate, and both disabled, in the five sizes — the box, the tick, the dash and the label scale together. indeterminate and checked are separate inputs and the dash wins while both are set. The lengths come from the shared --gog-control-checkbox-* scale that gog-radio-group reads too, which is why a checkbox and a radio line up on a form.

The label, and none

The control is a <label> around a real <input type="checkbox">, so the text is the accessible name — no for to wire up, pressing the text toggles the box. ariaLabel is for the case with no visible text, which is the only case it applies to. A long label wraps rather than pushing the box out of line.

Full width

Off by default: a checkbox is as wide as its label, so a row of them reads as a row. fullWidth fills the container — the dashed box here — leaving the rest of the line clickable.

Custom check icon — gogCheckboxIcon

The slot replaces the glyph inside the box, drawn through gog-icon so it takes the size the scale gives it. The box, its border, its fill and every state stay the component's. It is the checked glyph only: the indeterminate dash is drawn by the stylesheet, and a template does not reach it — the third checkbox shows it.

Select all

The classic parent row: checked when every child is, indeterminate when some are, and a press on it sets them all. The state is computed from the children — see the next example for why it has to be.

indeterminate is an input, not a model

A native checkbox resolves indeterminate on the first click; here the dash is drawn from the input, so a press changes checked and leaves indeterminate as it was. Press the checkbox below a few times: checked flips under the dash and nothing visible moves. That is what lets a parent row be driven from its children rather than from its own presses — and it means the state is yours to compute. Since 21.15.0 the element's own indeterminate property is written back after a press, so an input:indeterminate rule or a test reading the element agrees with the screen.

Two-way binding

checked is a model: [(checked)], or [checked] with (checkedChange).

Reactive forms, and the error a checkbox does not draw

A ControlValueAccessor: wire it with [formControl] or formControlName instead of [(checked)], never both. Validators.requiredTrue is how "you must tick this" is written. There is no errorMessage: a checkbox has no error line of its own, so the message belongs to the form around it. Disabling through the form ends up as disabled on the native input.

App-wide defaults — GOG_CONFIG

control.size sets the default size for every checkbox under the provider; an instance's own input still wins. In an app the provider goes in app.config.ts — see Global Configuration.

Accessibility

A native input inside a native label: the role, the state, the keyboard and the name all come from the platform rather than from ARIA. The box you see is a span and is not focusable; the input under it is.

  • Keyboard — Tab reaches it, Space toggles it.
  • State — checked is the input's own property, so no attribute appears for it. indeterminate, which has no native attribute, is announced through aria-checked="mixed" — the one piece of ARIA this component needs.
  • Name — the label, or ariaLabel when there is no visible text.

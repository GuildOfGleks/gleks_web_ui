gog-divider

Divider

A rule between two regions — horizontal or vertical, solid, dashed or dotted, with an optional label running through it. There is no hasLabel input: the two forms are told apart by whether anything was actually projected.

Variants

solid is the default; dashed and dotted read as weaker separations. Each is shown plain and with a label: with nothing projected the label collapses and the two halves of the rule meet as one line — the spacing around a label is its own padding for exactly that reason, so a plain divider has no notch in the middle.

Labels

Anything projected into the divider becomes its label and the rule splits around it. Because it is content rather than a label input, it takes markup — a word, an icon, a gog-tag.

Vertical

orientation="vertical" separates items along a row instead of stacking regions. It stretches to the height of a flex or grid parent that has one; --gog-divider-vertical-length is the floor when there is nothing to stretch to.

Inset

Indents the rule from the leading edge by --gog-divider-inset-size, so it lines up with the text of a list whose rows start with an icon instead of cutting across the whole row. Between the items of a real <ul>, use a border on the item instead — see Accessibility.

Per-instance tokens

--gog-divider-color, --gog-divider-thickness and --gog-divider-spacing are read only if set, so one divider can be heavier, coloured or roomier without touching the theme.

Accessibility

role="separator" on the host, with its orientation stated and named by its label. The rule itself is aria-hidden.

  • Role — role="separator" and an aria-orientation matching orientation, so a screen reader announces the break rather than skipping it.
  • Name — a projected label is the separator's accessible name, through aria-labelledby on the host , rather than content inside a role whose children ARIA treats as presentational. Keep labels short: every one is announced as a name. A divider with nothing projected stays unnamed.
  • Keyboard — none. A separator is not focusable.
  • Where it belongs — between groups of controls, or sections a reader moves between. Between the rows of a real <ul> the list already says where each item ends; draw the line with a border on the item there.

gog-collapsible

Collapsible

A headless expand/collapse primitive — inline, not a portal. It owns no markup of its own: project any element as the trigger with gogCollapsibleTrigger and any element as the panel with gogCollapsibleContent.

Overview

Import the component and its two directives.

A trigger and a panel, both projected in — [(open)] is two-way bindable. The trigger here is a native button styled with gogButton; the library draws none of its own.

Examples

Trigger host and state

A headless primitive: what it adds is the state, the ARIA wiring between trigger and content, and the height animation — the look is the trigger's. On a <div> the directive supplies what a button would have had: role="button", a tab stop and Enter/Space, so the second row is just as reachable as the first. disabled ignores presses and dims the trigger through --gog-collapsible-disabled-opacity; a programmatic [open] write still works.

The trigger is yours

Any markup inside the trigger, drawn from the open signal the page already holds — a chevron that flips, an icon and a label that swap. The directive also sets .gog-collapsible__trigger--open on the trigger while open, for a stylesheet that would rather rotate one icon.

Height

Open, the content is as tall as it is: --gog-collapsible-max-height defaults to max-content, which animates where interpolate-size is supported and snaps open elsewhere. Set a length only to cap a panel on purpose — the rest is clipped, as the last lines of this list are.

An overlay inside the content

Open the select: its list runs past the content's edge. The content clips only while it animates; open and settled it does not , so a dropdown, menu or tooltip inside is whole. A capped panel keeps clipping — that cap is the point of it.

Driven from outside

A collapsible without a gogCollapsibleTrigger is driven entirely by [(open)]. Its content still carries the id, aria-hidden and inert; the controls are the page's own, so wiring aria-expanded onto them is the page's job — gog-button's ariaExpanded does it.

Close when focus leaves

collapseOnFocusOut closes the panel once focus leaves both the trigger and the content: Tab past the last link, or click somewhere else on the page. Clicking the plain text inside keeps it open . Off by default, because an FAQ or a settings section read top to bottom should stay open wherever focus goes.

A list of independent collapsibles

Each item holds its own state, so several can be open at once — nothing closes a sibling. For one-at-a-time, keyboard movement between headers and a heading level, that is gog-accordion.

Accessibility

The trigger says whether it is expanded and what it controls; on an element that is not already a control, the directive makes it one.

  • Trigger — aria-expanded and aria-controls pointing at the content, plus aria-disabled while disabled. A <button> is left as written; any other element gets role="button" and tabindex="0". A host whose role or tabindex the consumer set keeps it.
  • Keyboard — Tab reaches the trigger; Enter or Space toggles it, on a <div> trigger as on a button.
  • Content — carries the id the trigger points at. Closed, it is aria-hidden and inert, so nothing inside it takes focus or is read out.
  • Name — the trigger's own text. A trigger that is only an icon needs an aria-label of its own.

Styling Tokens

The component itself renders no box — gogCollapsibleTrigger and gogCollapsibleContent style the elements you project, via global .gog-collapsible__* classes rather than a scoped stylesheet, since that content sits outside gog-collapsible's own view.

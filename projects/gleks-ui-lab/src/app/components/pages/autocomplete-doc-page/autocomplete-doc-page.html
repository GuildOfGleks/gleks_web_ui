gog-autocomplete

Autocomplete

A text field that suggests options as you type. It shares GogDropdownBase with Select — the same option accessors, placement, float label, error state and ControlValueAccessor — but its trigger is a real <input>, which is what makes it a separate control rather than a mode of the select.

Sizes

Five steps, also settable app-wide through GOG_CONFIG.control.size.

States

Empty with a placeholder, holding a value, disabled, with an error, and loading — [loading] puts a spinner in the trailing slot for a source that is still fetching. There is no chevron: the trigger is a text field, not a button, so nothing claims it is a list you open by clicking.

Clearable

clearable is opt-in, and it watches the text, not the selection: type two letters into the third field and the clear button appears before anything is picked, because on this control the two can disagree. Clearing empties both and emits gogSearch with an empty query, so a server-backed list resets with it. The spinner shares the trailing slot, and the field makes room for both.

Width

A field fills its container by default — the dashed box here. Unlike the two listbox controls, the trigger does not size to its content: it is an <input>, whose own width is the browser's default, so [fullWidth]="false" gives you that box and minWidth is the floor under it.

No visible label

ariaLabel names a field that has no label. With neither, the placeholder is the fallback accessible name — better than nothing, but it disappears the moment anything is typed.

Your own objects

optionLabel, optionValue and optionDisabled take a property path — dot-paths included — or a function, so a real DTO goes in unmapped. [optionValue]="null" hands back the option object itself. A gogDropdownOption template replaces one row, with the option plus selected, disabled and the resolved label in its context; [gogDropdownOptionTypeOf] types the option, so option.profile.role is checked under strictTemplates.

A disabled option, and the empty message

optionDisabled defaults to the disabled property, so an option carrying it needs no binding: the row stays in the list, reports aria-disabled, and neither the pointer nor Enter picks it. emptyMessage replaces the list when nothing matches — type zz into the second field.

Local filtering — filterMatch

Local filtering matches the query as a case-insensitive substring of the resolved label. filterMatch swaps in any predicate: type b into both — the default keeps Dublin, Lisbon and Zagreb beside the five cities that start with B; the prefix matcher keeps only those five.

Two-way binding, and the text that is not the value

The field holds two things: what is typed, and what is committed. Pick Berlin, then edit the text — the value stays Berlin until the edit resolves, and Esc or clicking away snaps the text back. That is forceSelection, on by default: a user who types one more character to refine a search does not silently lose what they had picked.

Free text — [forceSelection]="false"

For a create-as-you-type flow, where the text itself is the answer. Neither blur nor Esc touches what was typed — Esc only closes the panel — and value is dropped as soon as the text stops matching, so the two never disagree. Read the text from gogSearch, not from value.

Reactive forms

errorDisplay="auto" shows the error once the control is touched and invalid: focus the field and leave it without picking. Text that matches no option leaves the value null, so a required field stays invalid however full the box looks — the point of forceSelection being on.

Float label

'none' keeps the label above the field; 'in', 'on' and 'over' rest it inside until focus or a value moves it clear — each shown empty, then holding a value. floatLabelShowPlaceholder brings the placeholder back once the label has floated.

App-wide defaults — GOG_CONFIG

control.size and the autocomplete keys set the defaults for every field under the provider; an instance's own input still wins. Here the second field opens only after two letters, and the third reports one query a second. In an app the provider goes in app.config.ts — see Global Configuration.

Searching, and a server behind it

openOnFocus — on by default — opens the panel with the whole list the moment the field is focused, before minLength would have let anything through; for a short, known list that is the difference between a combobox and a text field the user has to guess at. Off, nothing opens until enough has been typed. Focus each field without typing, then type one letter:

gogSearch is debounced — searchDebounce, 300 ms by default — so a lookup fires once the typing settles. Type a word at speed into each and compare the counters: 0 emits on every keystroke, which a local source can afford and a server-backed one cannot.

A server-backed field is three inputs: (gogSearch) runs the lookup, [loading] shows it is running, and [filterLocal]="false" stops the answer being filtered a second time. That last one is the bug worth naming: the server matched on fields this component cannot see, so filtering its reply against the same query silently drops rows. This lookup also matches the country — type germany.

The panel — appendToBody

The panel renders inline by default and is clipped by any scrolling or overflow: hidden ancestor. appendToBody moves it into <body> and positions it against the trigger. Type in the first two: only the appended one survives its box. dropdownWidth and dropdownMaxHeight take any CSS length and apply only while the panel is appended — an inline panel matches the trigger.

Virtualized options — virtualize

virtualize renders only the rows in view. Both fields hold the same 10 000 options: unwindowed, that is 10 000 DOM rows to show about six — measured in Chrome, 512 ms before the panel appears, against 21 ms windowed. The scrollbar looks the same either way, because spacers stand in for the rows that are not there.

Off by default, and never switched on at some row count. A windowed list behaves differently in ways nothing about the data predicts: Ctrl+F finds only the rendered rows, and CSS targeting :last-child matches the last rendered one. Set it per field, or app-wide with GOG_CONFIG.dropdown.virtualize. aria-setsize and aria-posinset keep the announced count real, and the arrows walk the whole list — End reaches the last option. Focus never moves, which is how this differs from the select: a combobox keeps focus in its input. gogLoadMore is not a substitute and the two compose — that one keeps the records the server sends small, this one the rows the browser builds.

Accessibility

The trigger is a real <input role="combobox">. DOM focus never leaves it: the highlighted row is pointed at with aria-activedescendant rather than being focused, which is what makes this a combobox rather than a select, and why typing keeps working while the panel is open. The rows are role="option" and are never tab stops.

  • Keyboard — the arrows highlight, Home/End jump to the ends, Enter picks the highlighted row (and does nothing when there is none), Esc closes the panel, Tab closes and moves on.
  • Name — label, or ariaLabel; use inputId to wire your own <label for>.
  • Error — errorMessage sets aria-invalid="true" and an aria-describedby pointing at the message.
  • Loading — the spinner is aria-hidden, so the host carries aria-busy while loading is on.
  • Clear button — named by clearAriaLabel, or GOG_CONFIG.labels.clearSelection.

Inputs — autocomplete's own

Inputs — shared with Select

These come from GogDropdownBase and behave as they do on Select. The panel's search box is not among them: an autocomplete's trigger already is the search box, so filter, filterPlaceholder, filterPosition and filterEmptyMessage do not exist here — they did until 21.16.0, deprecated and doing nothing, and binding one is now a compile error. Use placeholder and emptyMessage. filterMatch still applies, since it plugs into filterLocal's own matching.

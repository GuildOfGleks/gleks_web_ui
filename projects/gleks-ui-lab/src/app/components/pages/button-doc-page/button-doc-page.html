gog-button  ·  [gogButton]

Button

A debounced action button with four variants, five sizes, and built-in loading, disabled, and full-width states — plus, since , a [gogButton] directive that gives the same look to a link you own.

Overview

Import the component and drop it into a template.

Basic usage — a primary button that reacts to a click. Listen to (gogClick), not (click): gogClick is the one that respects debounce and loading.

Variants & sizes

Every combination of the four variants and five sizes.

Severity

severity says what the action means; variant says how loudly it is drawn. The two are orthogonal, so this is not a fifth variant — every cell below is a real combination, and a ghost delete is still a delete. "accent" is the default and the absence of a claim, which is why every other button on this page needs no opt-out.

Now switch the theme with the toggle in the header and look again. Three decisions show at once. A filled button's label is the colour its theme states for that status, per status: under primeng, success, warning and info carry a near-black label because white would be unreadable on them, while danger keeps white. Hover and press deepen the fill away from that label, so a state only makes it easier to read. And the outlined and ghost labels are the status hue mixed halfway toward the page's ink, because the raw hue as body text clears WCAG AA in only five of the eleven themes. The Theming guide describes the layering behind it.

Press feedback, with animations off

Hold any of these down. The background deepens one step past its own hover, so the press reads even while the pointer is already hovering — and it is a state rather than a movement. Turn on prefers-reduced-motion: reduce (DevTools → Rendering → Emulate CSS media feature) and the scale() goes away while the colour stays. The last button sets its own press colour inline, through the instance tokens --gog-button-press-bg / --gog-button-press-color.

A theme sets the same thing for every button of a variant, and retimes or removes the movement for all of them:

Until 21.9.0 the scale was the whole press, so with animations off a press showed nothing. The ripple is not meant to cover that: it is off by default and suppressed under reduced motion, because a ripple is decoration and a press state is not.

Disabled

One disabled button per variant — the disabled state must stay legible on every colour.

Loading

Loading swaps the label for a spinner and blocks clicks — through aria-disabled rather than the native disabled, so focus stays on the button. On a type="submit" button a click while loading does not submit the form. The spinner scales with the button size.

Full width

fullWidth stretches the button to its container — the dashed box here. The directive takes the same input, on a <button> or a link.

Content and icons

Text, an icon beside text, an icon alone, and a label too long for one line. An icon-only button has no visible label, so ariaLabel is required — it names the inner <button>, unlike a plain aria-label attribute on <gog-button>. Beside a label, put the icon in as a plain <gog-icon>: it is centred and spaced --gog-button-gap away, with no margin or &nbsp; of your own. Every button of one size is one height, icon or not — read each column down. A long label wraps once its container is narrower than it, and the button grows taller with it.

ARIA state — a toggle and a disclosure

The component hides the real <button>, so [attr.aria-pressed] written on <gog-button> lands on a host with no role and reaches no assistive tech — it compiles and looks right, which is why it is worth a demo. Use the inputs: ariaPressed, ariaExpanded, ariaControls, ariaHasPopup and ariaCurrent — the last one marks the current item of a set, the way gog-paginator marks its current page.

Press "Mirror layout": a toggle that is on keeps an inset ring (--gog-button-<variant>-toggled-shadow) for as long as aria-pressed is "true" or "mixed" — a ring rather than a fill, because hover and press already own the background. The off state renders aria-pressed="false" rather than dropping the attribute: null means "not a toggle button", false means "a toggle that is off", and to a screen reader those are two different controls.

Debounce guard

Clicks are throttled leading-edge: the first fires immediately, further clicks are dropped for debounce ms (default 300). Click each one rapidly and compare the counters: 0 accepts every click, 1000 one a second. A dropped click is cancelled, so on a type="submit" button it does not submit the form either.

Native type semantics

type is forwarded to the native <button>, so a submit or reset button inside a <form> works as it would without the component — and it defaults to "button", so a button in a form submits only when you ask. A loading submit button does not submit.

App-wide defaults — GOG_CONFIG

control.size and button.debounce set the default for every button under the provider; an instance's own input still wins. This example provides the config on itself so that it reaches only its own buttons — in an app it goes in app.config.ts. See Global Configuration for every key.

Links that look like buttons — [gogButton]

gog-button renders its own <button>, so it can never be a link. The directive inverts that: the element stays yours and [gogButton] only gives it the look.

The component and the directive side by side, in every variant. The directive has no disabled, loading or ARIA inputs: those are attributes of the element it is written on, so a disabled one is a <button disabled>.

The selector is a[gogButton], button[gogButton] — deliberately not a bare [gogButton]. On a <div> the result would look like a button while being invisible to the keyboard and to assistive technology.

Which one to reach for

The component when the button acts on the page: it owns loading (a centred spinner it projects), debounce click throttling and the gogClick output — none of which a bare element can provide. The directive when the element must be a link, or must keep directives of its own. routerLink, href, target, download, type="submit" and the rest keep working because they were never brokered through an input in the first place.

That is also why the library has no @angular/router dependency — a component that took a routerLink input would force the router on every app that installs the package.

Two things the directive deliberately does not do: no disabled on an <a> (there is no such thing — drop the href or render a real <button>), and no loading state (the spinner is a projected child, which a directive cannot add without taking over the element's content). Its styles live in the global styles/button.css, pulled in by index.css, because emulated encapsulation cannot reach an element declared in your template.

Accessibility

gog-button renders a native <button>, so it is one tab stop, Enter and Space press it, and it is announced as a button by its content. Everything a screen reader needs goes on that inner element through inputs, never as attributes on the <gog-button> host:

  • Name — the projected text, or ariaLabel when there is none (an icon-only button).
  • State — ariaPressed for a toggle, ariaExpanded + ariaControls + ariaHasPopup for a disclosure or popup trigger, ariaCurrent for the current item of a set.
  • Disabled — disabled takes the button out of the tab order; loading keeps it focusable with aria-disabled, and keeps its label in the accessible name , so a button that was just pressed still says what it is.
  • Directives on a gog-button — gogTooltip, [gogMenuTrigger] and gogBadge write their ARIA onto the inner <button> .

[gogButton] needs none of these inputs: it styles an element you own, so write the attributes on it directly — it draws the toggled ring off the aria-pressed you wrote.

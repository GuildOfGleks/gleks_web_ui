gog-dialog

Dialog

A service-driven modal outlet — mount <gog-dialog /> once and open any component as its body through DialogService. Supports stacking, dragging, a built-in focus trap, and a ready-made confirmation dialog.

Overview

Import DialogComponent and mount <gog-dialog /> once, near the root of the app. Every DialogService.open() renders through that one outlet. Both come from @guildofgleks/ui/dialog, with the confirmation dialog and the dialog tokens — a dialog opened only behind a lazy route keeps its own code out of the initial bundle. What it imports from the root package (the button, icon and scroll area it renders) loads wherever the root package already does.

Basic usage — the library's ConfirmationDialogComponent for a confirm/cancel prompt. It shows the question as its own heading, so the dialog is named by that heading: ariaLabelledBy on the config and titleId in its data are the same id. afterClosed resolves with true, false, or undefined when dismissed.

Examples

Modal, closable, draggable, role, title

modal, closable and draggable are all on by default. Off, modal drops the dimmed backdrop, the focus trap and the body scroll lock, and a press on the page reaches the page and leaves the dialog open ; closable removes the close button, Escape and the backdrop press, leaving the content's own buttons; draggable keeps the header but stops it moving. Without a title the header holds only the close button — and the dialog has no name, which dev mode warns about.

Your own component

Any component can be the body: it reads DIALOG_DATA and closes itself through DIALOG_REF, and what it closes with resolves afterClosed — Save with an object, Cancel and the close button with undefined. The select needs appendToBody: the dialog's body is a scroller, and a list rendered inside it is clipped under the header. Escape closes the open list first and the dialog only on the next press ; a control of your own can claim the key the same way, with preventDefault().

width and maxWidth

Both are CSS lengths written onto the panel; maxWidth wins when the two disagree. Unset, the panel is as wide as its content, up to 90vw.

Long content

The body scrolls inside the panel, capped by --gog-dialog-body-max-height, and the header — with the close button and the drag handle — stays put.

closeIconName and closeIconTemplate

Only the look of the close button changes: it keeps its name, its focus ring and Escape.

Stacking, and closeAll

Open one, then another from inside it — the body injects DialogService like any other consumer. Each opens above the last; Escape closes only the top one, and closing the last returns focus to what had it before the first opened. Close all resolves every open dialog's afterClosed with the value it is given.

Accessibility

The panel is role="dialog" (or alertdialog), aria-modal while modal, and named by its title through aria-labelledby.

  • Name — every dialog needs a title or an ariaLabelledBy; dev mode warns about one with neither. When the content carries its own heading, point ariaLabelledBy at it instead of repeating it as a title — for ConfirmationDialogComponent, pass the same id as data.titleId.
  • Keyboard — the top dialog takes focus; Tab and Shift+Tab cycle inside a modal one, a non-modal one lets focus leave. Escape closes the top dialog, after anything inside that claimed it. Closing the last one returns focus to what had it before the first opened.
  • Dismissing — Escape, the close button, and a press that both starts and ends on the backdrop; a drag that starts in the panel and is released outside does not close. All three resolve afterClosed with undefined.
  • Close button — named by closeAriaLabel, or GOG_CONFIG.labels.closeDialog app-wide.
  • Overlays inside — a tooltip or a dropdown opened from a dialog stacks above it: the panel raises --gog-tooltip-z and --gog-dropdown-z.

Injection tokens

ConfirmationDialogComponent

A ready-made body for confirm/cancel prompts — pass it as component with a ConfirmDialogData as data: { title, titleId?, description, confirmText, cancelText }. It closes itself with true on confirm and false on cancel.

Styling Tokens

Every CSS custom property the dialog paints with. Override any of them — on a single instance, a subtree, or a theme — to restyle it. See the Theming guide for the full token-layering model, or the Theme Generator to tweak these live.
